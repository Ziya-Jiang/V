# RGB-D 书本厚度与夹爪开口算法说明

## 1. 文档目的

本文说明 `book_thickness_pipeline.py` 如何从 RGB-D 数据中：

1. 找到每一本可见书脊。
2. 区分书脊正面与因斜视产生的书本侧面。
3. 计算书脊的毫米厚度。
4. 拒绝无法可靠测量的候选。
5. 在多帧模式下融合多个视角。
6. 计算双指夹爪的建议预张开宽度。

算法面向机器人抓取规划，不是计量认证系统。输出宽度必须配合夹爪力控、电流阈值和
碰撞检测使用。

## 2. 问题定义

### 2.1 需要计算的量

目标量是书脊左右边界之间的物理距离：

```text
book_thickness_mm
```

它不是：

- RGB 图像中的水平包围框宽度。
- 书本在图像中的完整可见轮廓宽度。
- 书本封面向后延伸的深度。
- 书架平面上的书本占用宽度。

对于倾斜书本，算法沿书脊自身的横向轴测量，而不是沿图像水平方向测量。

### 2.2 主要困难

实际场景包含以下误差来源：

- 书脊在 RGB 图像中倾斜。
- 相机不能正对所有书本。
- 书本排列松散时会看到封面、页块或侧面。
- 语义分割可能把书脊与侧面合成同一个实例。
- 深度图存在空洞、边缘混合、多径和量化误差。
- RGB 与 depth 的分辨率可能不同。
- 单帧无法观察被遮挡的真实边界。
- 多帧中的同一本书需要可靠匹配。

其中最危险的是“侧面被算入书脊宽度”，因为它会产生系统性的厚度偏高。当前实现使用
深度多平面分解和安全拒绝机制处理该问题。

## 3. 输入模式

### 3.1 通用单帧模式

直接提供三个路径：

```bash
python book_thickness_pipeline.py \
  --rgb /path/to/rgb.png \
  --depth /path/to/depth.png \
  --intrinsics /path/to/intrinsics.json \
  --output /path/to/result
```

通用模式不要求 Record3D、confidence、位姿或固定目录结构。

支持的深度格式：

- 单通道 PNG、TIFF。
- 二维 `.npy`。
- 包含 `depth` 数组或唯一数组的 `.npz`。

深度单位约定：

- 浮点深度默认单位为米。
- 16 位及以上整数深度默认单位为毫米。
- 其他单位通过 `--depth-scale` 指定“米/数值”。

内参可使用：

```json
{
  "fx": 677.7016,
  "fy": 677.9246,
  "cx": 490.9557,
  "cy": 270.4970
}
```

或标准 3×3 相机矩阵：

```text
fx  0  cx
0  fy  cy
0   0   1
```

内参必须对应 RGB 图像坐标系，depth 必须已经对齐到 RGB。

### 3.2 Record3D 单帧模式

```bash
python book_thickness_pipeline.py CAPTURE \
  --single-frame-rgbd \
  --reference-frame 24
```

该模式读取：

- `CAPTURE/rgbd/24.jpg`
- `CAPTURE/rgbd/24.depth`
- `CAPTURE/metadata` 中的尺寸与内参

它不读取 `.conf`，也不使用 `metadata.poses`。

### 3.3 Record3D 多帧模式

```bash
python book_thickness_pipeline.py CAPTURE \
  --frames 0,12,24,36,48,60,71 \
  --reference-frame 24
```

多帧模式额外使用：

- Record3D 深度 confidence。
- 每帧相机内参。
- ARKit 相机位姿。

## 4. 坐标系与单位

### 4.1 图像坐标

RGB 像素使用：

```text
u：向右
v：向下
```

### 4.2 相机坐标

反投影后的相机坐标使用：

```text
X：相机右方
Y：相机下方
Z：相机前方
```

内部 3D 单位统一为米，最终厚度与夹爪开口输出为毫米。

### 4.3 相机内参

相机矩阵为：

```text
    [fx  0  cx]
K = [0  fy  cy]
    [0   0   1]
```

像素 `(u, v)` 对应的未归一化相机射线为：

```text
r(u, v) = [(u - cx) / fx, (v - cy) / fy, 1]
```

深度为 `z` 时，3D 点为：

```text
P = z · r(u, v)
```

## 5. 算法总流程

```text
RGB
 └─ SAM3 书本实例分割
     └─ 掩码清理与重复实例抑制
         └─ PCA 拟合书脊长轴/横轴及轮廓边界

Depth + K
 └─ 有效深度筛选与反投影
     └─ 每本书 RANSAC 多平面分解
         └─ 全画面书脊法向共识
             └─ 每本书选择主书脊平面
                 ├─ 无可见侧面：保留 RGB 边界
                 ├─ 有可见侧面：裁剪到书脊/侧面交界
                 └─ 几何不可靠：拒绝测量

修正边界 + 书脊平面
 └─ 射线/平面求交
     └─ 毫米厚度
         ├─ 单帧低质量结果
         └─ 多帧关联、异常值剔除与鲁棒融合
             └─ 不确定度 + 安全间隙
                 └─ 建议夹爪开口
```

## 6. RGB 书脊实例分割

### 6.1 SAM3 检测

默认文本提示为：

```text
book
```

默认阈值：

- SAM3 processor 初始阈值：0.10。
- 最终检测分数阈值：0.50。
- 实例 NMS IoU：0.40。

### 6.2 初始几何过滤

候选需要满足：

- 包围框宽度至少 6 px。
- 包围框高度至少 100 px。
- 宽度不超过图像宽度的 18%。
- 高度不超过图像高度的 65%。
- 拟合后的书脊宽度至少 5 px。
- 拟合后的有效长度至少 100 px。

这些阈值用于去除整层书架、背景和小碎片。对于分辨率明显低于 540p 或书本只露出很小
区域的图像，需要重新标定最小高度阈值。

### 6.3 掩码清理

每个实例只保留面积最大的连通区域，并填充内部孔洞。这样可以避免书脊文字、标签或
反光造成的掩码破洞影响边界拟合。

### 6.4 重复实例抑制

候选按分数从高到低处理。同层候选先检查包围框重叠，再计算掩码 IoU。掩码 IoU 超过
默认阈值 0.40 时，只保留分数更高的实例。

## 7. 书脊二维几何拟合

### 7.1 PCA 主轴

将掩码内所有像素组成二维点集，计算协方差矩阵：

```text
C = (1 / (N - 1)) Σ (p_i - p_mean)(p_i - p_mean)^T
```

最大特征值对应的特征向量定义为书脊长轴：

```text
l = long_axis
```

与其垂直的向量定义为书脊横向轴：

```text
t = transverse_axis
```

因此，即使书本在图像中倾斜，厚度方向仍跟随书脊自身方向。

### 7.2 分段边界拟合

把掩码像素投影到 `(l, t)` 坐标：

```text
s_i = (p_i - p_mean) · l
q_i = (p_i - p_mean) · t
```

处理步骤：

1. 使用长轴坐标的 3%–97% 分位范围。
2. 再从两端各去掉 13%，减少书顶、书底和书架边缘影响。
3. 将剩余长轴区间分成 32 段。
4. 每段使用横轴坐标的 1% 和 99% 分位作为左右边界。
5. 分别对左右边界执行一次线性拟合。
6. 在书脊中部计算初始宽度。

该宽度是 RGB 轮廓宽度，仍可能包含侧面，必须经过后续深度平面检查。

## 8. 深度预处理

### 8.1 RGB 掩码映射到 depth

RGB 掩码以面积插值映射到 depth 分辨率。深度像素的掩码覆盖率需要达到 0.35。

如果 RGB 和 depth 分辨率不同，算法假设二者视场和宽高比已经对齐。通用输入的宽高比
相差超过 2% 时会直接报错。

### 8.2 深度有效范围

只接受：

```text
0.1 m < depth < 5.0 m
```

同时删除 NaN、Inf 和零值。

### 8.3 confidence

Record3D 多帧模式优先使用 confidence 等级 2。如果高置信度点少于 8 个，则回退到
等级不低于 1 的点。

通用单帧模式没有 confidence，所有通过数值检查的深度点作为可用点处理。输出中的
`uses_confidence = false` 明确记录这一事实。

### 8.4 深度统计

先计算书本区域深度中位数和 MAD：

```text
MAD = median(|z_i - median(z)|)
```

用于深度统计的核心点满足：

```text
|z_i - median(z)| ≤ max(12 mm, 4.5 × 1.4826 × MAD)
```

多平面分解使用范围检查后的表面点，而不是只使用该窄深度核心，否则真实侧面可能在
进入平面分解前就被错误删除。

## 9. 深度多平面分解

### 9.1 为什么不能只拟合一个平面

当书本排列松散且相机斜视时，一个 SAM 掩码可能同时包含：

- 书脊正面。
- 封面或页块侧面。
- 少量背景或相邻书本。

如果对全部点直接做一次最小二乘平面拟合，结果可能位于两个真实平面之间，或者选择
面积更大的侧面。因此当前算法先进行多平面分解。

### 9.2 RANSAC 平面模型

平面表示为：

```text
n · P + d = 0
```

其中 `n` 是单位法向量，`d` 是平面偏移。

每个实例最多提取三个平面。每次提取流程：

1. 从当前剩余点中随机取三个点生成平面。
2. 执行 96 次 RANSAC 假设。
3. 点到平面距离不超过 6 mm 时视为内点。
4. 候选点超过 2000 时，随机选 2000 点生成和评分假设。
5. 使用全部点重新计算最佳假设的内点。
6. 对内点执行 SVD 平面拟合，最多迭代细化三次。
7. 删除该平面的内点，再提取下一个平面。

每个候选平面至少需要：

```text
max(12 个点, 当前实例总点数的 4%)
```

### 9.3 平面纵向覆盖率

仅靠内点数量不足以判断书脊。背景小块或标签也可能形成平面，因此还计算平面内点沿
书脊长轴的覆盖率：

```text
coverage =
  (longitudinal_95% - longitudinal_5%) / fitted_spine_length
```

真正书脊平面通常沿书脊高度具有较高覆盖率。

## 10. 全画面书脊法向共识

### 10.1 目的

单本书的面积最大平面未必是书脊。如果相机从侧面观察，封面侧面可能比书脊正面占据
更多像素。算法利用“同一画面大部分书脊方向接近”这一场景先验，估计共同书脊法向。

### 10.2 参与共识的候选

候选平面需要满足：

- 纵向覆盖率至少 45%。
- 在当前书本中的内点比例至少 6%。
- 法向量垂直分量约束 `|n_y| ≤ 0.55`。
- 相对相机光轴的夹角不超过 75°。

### 10.3 聚类与权重

每个候选的权重为：

```text
weight =
  inlier_count
  × longitudinal_coverage
  × (0.35 + 0.65 × |n_z|)
```

对每个候选统计法向夹角在 22° 内的总权重，选择权重最大的法向簇。最后对该簇法向
做加权平均并归一化，得到：

```text
expected_spine_normal
```

该机制倾向于选择覆盖书本数量多、纵向完整且更接近正视方向的共同书脊平面。

## 11. 单本书主书脊平面选择

对每本书，在纵向覆盖率至少 45% 的候选中，选择与
`expected_spine_normal` 夹角最小的平面。

选择后执行安全检查：

- 主平面内点比例至少 35%。
- 主平面纵向覆盖率至少 55%。
- 主平面与全局书脊法向夹角不超过 32°。
- 主平面相对相机光轴的观察夹角不超过 60°。

不满足时拒绝该候选，不输出厚度。

## 12. 书本侧面检测与边界裁剪

### 12.1 侧面候选

除主书脊平面外，第二平面需要同时满足以下条件才视为侧面：

- 内点比例至少 4%。
- 沿书脊长轴覆盖至少 40%。
- 与主书脊平面的法向夹角至少 35°。
- 横向中位位置距离掩码中心至少为掩码宽度的 15%。

最后一个条件要求第二平面位于书脊边缘，避免把书脊中央标签误识别为侧面。

若所有侧面候选的总占比超过 40%，说明掩码主要不是可靠书脊，直接拒绝。

### 12.2 使用主平面支持区重新拟合边界

只使用主书脊平面的深度内点：

1. 使用长轴坐标 8%–92% 的范围。
2. 分为 16 个长轴区间。
3. 每段至少需要 3 个主平面内点。
4. 每段以横向 2% 和 98% 分位作为主平面左右支持边界。
5. 至少 6 个有效区间。
6. 对左右支持边界分别执行线性拟合。

如果侧面位于左侧，则使用主平面左支持边界替代原 RGB 左边界；右侧同理。

只有裁剪量满足以下条件才执行修正：

```text
trim_px > max(1.5 px, 原掩码宽度的 4%)
```

如果检测到侧面却无法得到有效裁剪边界，候选会被拒绝，避免继续使用包含侧面的原始
轮廓宽度。

修正后的宽度还必须满足：

```text
35% × 原宽度 ≤ 修正宽度 ≤ 原宽度
```

### 12.3 诊断量

算法同时保留：

- `silhouette_thickness_mm`：原始完整轮廓在主平面上的宽度。
- `side_trim_mm`：侧面裁剪掉的物理宽度。
- `boundary_trim_left_px`：左侧裁剪像素。
- `boundary_trim_right_px`：右侧裁剪像素。
- `side_face_fraction`：侧面平面内点比例。

## 13. 三维厚度计算

### 13.1 射线与平面求交

书脊平面为：

```text
n · P + d = 0
```

边界像素射线为 `r`，交点写为：

```text
P = λr
```

代入平面方程：

```text
λ = -d / (n · r)
```

分别计算修正后左、右边界的交点：

```text
P_left
P_right
```

书本厚度为：

```text
thickness_mm = 1000 × ||P_right - P_left||
```

只保留 3–100 mm 的结果。

### 13.2 为什么该方法能校正斜视

两个边界点都在实际书脊平面上求交，因此距离是在 3D 平面中计算，不是简单使用：

```text
像素宽度 × 中心深度 / fx
```

对于可可靠拟合的书脊平面，射线/平面交点可以校正透视缩短。但是它不能恢复完全被
遮挡的真实边界；这种情况必须拒绝或增加视角。

## 14. 安全拒绝机制

常见拒绝原因及含义：

- `insufficient_depth_surface`：有效深度点不足。
- `no_depth_plane`：无法形成稳定深度平面。
- `insufficient_plane_coverage`：没有纵向覆盖足够的平面。
- `low_spine_plane_inlier_ratio`：主书脊平面内点比例低于 35%。
- `low_spine_plane_coverage`：主书脊平面纵向覆盖低于 55%。
- `inconsistent_spine_plane_normal`：与全局书脊方向偏差超过 32°。
- `grazing_view_angle`：相机观察角超过 60°。
- `side_face_dominates_mask`：侧面占比超过 40%。
- `side_face_boundary_unresolved`：主平面支持边界无法拟合。
- `side_face_boundary_ambiguous`：检测到侧面但裁剪量不可靠。
- `invalid_corrected_spine_width`：修正宽度比例不合理。
- `thickness_out_of_range`：厚度不在 3–100 mm。

被拒绝候选：

- 不写入 `gripper_openings.json`。
- 不产生机器人抓取开口。
- 写入 `frame_statistics[].rejected_detections`。
- 在 `rejected_books_overlay.png` 中以红色显示。

安全原则是宁可少输出，也不把高风险宽度传给机器人。

## 15. 多帧关联

单帧模式跳过本节。

### 15.1 相机到世界坐标

Record3D 位姿中的四元数和平移用于构造相机到世界变换：

```text
P_world = R_wc P_camera + t_wc
```

实现中还处理 ARKit 与计算机视觉相机坐标轴方向的差异。

### 15.2 参考帧

参考帧负责：

- 书本实例编号。
- 最终二维边界。
- 输出总览图和逐书裁剪图。

书本按每层从左到右编号：

```text
S1-01, S1-02, ...
S2-01, S2-02, ...
S3-01, S3-02, ...
```

### 15.3 跨帧代价

参考帧书本中心先投影到目标帧。匹配代价为：

```text
cost =
  pixel_distance
  + 0.15 × min(world_distance_mm, 50)
```

同一层书架内使用匈牙利算法求一对一匹配。默认最大匹配代价为 60 px，超过该阈值的
匹配被丢弃。

## 16. 多帧鲁棒融合

### 16.1 初始中位数

对同一本书的所有有效厚度：

```text
m = median(thickness_i)
σ_robust = 1.4826 × median(|thickness_i - m|)
```

### 16.2 异常值剔除

保留：

```text
|thickness_i - m| ≤ max(3 mm, 3.5 × σ_robust)
```

最终厚度是保留值的中位数。

### 16.3 重复性

```text
repeatability_mad_mm =
  1.4826 × median(|thickness_i - final_median|)
```

单帧只有一个值，因此该字段为 0。这只表示没有第二次观测，不能解释为零误差。

## 17. 不确定度估计

### 17.1 像素采样项

横向一个 RGB 像素对应的毫米尺度为：

```text
metric_per_pixel_mm =
  depth
  × sqrt((t_x / fx)² + (t_y / fy)²)
  × 1000
```

基础像素项：

```text
pixel_floor =
  median(metric_per_pixel_mm)
  × √2
  × 0.85
```

### 17.2 斜视放大项

设书脊平面观察夹角为 `θ`：

```text
view_factor = 1 / max(cos θ, 0.5)
```

最终像素项乘以多帧 `view_factor` 中位数。角度越斜，同样一个像素的边界误差对应更大
物理误差。

### 17.3 其他项

- 标定下限：0.8 mm。
- 检测到并修正侧面时的附加项：1.5 mm。
- 多帧随机项：

```text
random_component = repeatability / sqrt(number_of_used_views)
```

### 17.4 95% 工程不确定度

```text
U95 = max(
  1.5 mm,
  1.96 × sqrt(
    random_component²
    + pixel_floor²
    + calibration_floor²
    + side_face_floor²
  )
)
```

该值是抓取规划用的工程估计，不是计量机构校准后的置信区间。

## 18. 质量等级

初始等级为 `high`。

满足任意一项时降为 `medium`：

- 有效视角少于 4。
- `U95 > 3 mm`。
- 中位匹配残差大于 25 px。
- 任一使用视角检测到侧面。
- 任一使用视角的观察角大于 40°。

满足任意一项时降为 `low`：

- 有效视角少于 2。
- `U95 > 5 mm`。
- 中位匹配残差大于 45 px。

因此单帧结果必然为 `low`。`low` 不等于程序失败，而是表示不能直接用于无人值守抓取。

## 19. 夹爪开口

建议预张开宽度：

```text
recommended_gripper_opening_mm
= thickness_mm
 + uncertainty_95_mm
 + gripper_clearance_mm
```

默认：

```text
gripper_clearance_mm = 3.0
```

这只是接近书本前的预张开值。实际闭合必须依赖：

- 力控。
- 力矩限制。
- 电机电流阈值。
- 触觉或接触检测。

## 22. 已知限制

### 22.1 单帧不可观测性

如果真实书脊边界被侧面完全遮挡，单帧不能恢复不可见边界。算法只能：

- 根据平面交界裁剪可见侧面；或
- 拒绝测量。

不能通过增加模型复杂度可靠“猜出”完全不可见的真实厚度。

### 22.2 深度分辨率

Record3D 低分辨率 LiDAR 深度可能没有足够点数分离很窄书脊与侧面。L515 等与 RGB
同分辨率或高分辨率对齐深度更适合多平面分解。

### 22.3 深度边缘混合

在书脊—侧面交界、书本—背景交界处，一个深度像素可能混合多个表面。6 mm RANSAC
阈值和分位数边界能降低影响，但不能完全消除。

### 22.4 全局方向先验

算法假设画面内多数书脊方向接近。如果大部分书本都以不同角度散乱摆放，全局法向共识
可能失效，导致更多安全拒绝。

### 22.5 透明、反光与吸光材料

透明塑封、镜面封面或深色吸光材质可能产生无效深度。此时应增加视角、调整照明或使用
其他深度传感器。

### 22.6 书架层区域

当前部署使用三个归一化书架区域：

```text
S1: 0.18H–0.45H
S2: 0.43H–0.70H
S3: 0.66H–0.94H
```

这是当前书架场景先验，不是通用书架检测。相机位置或书架布局显著变化时，应把区域改为
配置参数或自动检测层板。

## 25. 设计原则总结

本算法采用以下优先级：

```text
安全拒绝
  > 防止侧面导致厚度偏高
  > 跨视角一致性
  > 单帧检测数量
```

核心原则是：

1. RGB 决定高分辨率语义候选和初始边界。
2. depth 决定物理尺度、平面方向和侧面分离。
3. 全局书脊方向帮助单书避免选错平面。
4. 可见侧面必须裁剪，无法裁剪必须拒绝。
5. 单帧结果必须保持低质量标记。
6. 只有通过几何检查的书本才允许生成夹爪开口。
