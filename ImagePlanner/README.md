# ImagePlanner：腕部 RGB 抓取的离线最小验证

当前条件：有真机和 RGB 图像，没有现成示范、标注、内参或动作日志。先采集示范，再验证视觉子目标是否稳定、能否预测留出示范的关键阶段。此项目没有机器人控制或相机连接代码，不会移动真机。

## 第一轮采集

以下数量是启动建议，不是统计充分性或成功率保证。

1. 固定腕部相机安装、图像分辨率、裁剪方式和夹爪；选同一个刚性物体，在同一桌面上做俯视抓取，先固定物体朝向。
2. 用现有人工操作方式完成抓取。每次保存独立的原始 RGB 视频或按时间命名的图片目录，保留完整过程；建议先录 15 次成功示范，10 次训练、5 次测试。按完整抓取回合划分，不能把同一段视频的不同帧分到两边。
3. 让物体起始位置在左、中、右和不同距离上有适度变化，但保持可见。保留失败回合并人工记录原因，第一版拟合只用成功示范。
4. 每次从完整序列里另选四张原图：初始、横向对齐、接近到抓取前、夹爪闭合附近且物体仍清晰可见。四张图只用于本版低成本标注；完整录像供后续视频/轨迹模型使用。
5. 在四帧原图上标出目标框 `[x, y, width, height]`，单位为像素，左上角为原点。不要先把物体居中或缩放，也不要在物体完全遮挡时凭空补框。闭合附近无法标注的回合应单独记录，不能当作完整可见序列输入本版工具。
6. 人工记录是否真正夹住、是否抬离桌面、是否滑落。图像中的物体变大、夹爪闭合，都不能单独证明抓取成功。

暂时不需要内参或深度来计算二维框误差。未来接入控制器时，仍需另行建立视觉变化到机器人运动的映射，并明确姿态、尺度、可达性和接触反馈。

物体夹稳后与腕部相机一起运动，因此目标图像可能不再变化。抬升完成不能由这个物体框序列可靠判定；后续需要机械臂位移与抓取反馈。

## 本版模型实际做什么

输入：人工目标框、人工关键阶段索引、固定相机与物体标识。图像仅用于尺寸检查和引用，**没有图像检测器，也没有从 RGB 学习表征**。

表示：目标在原图中的归一化中心，以及归一化宽高的对数。这保留位置与尺度，但不表达完整三维姿态、深度或接触。

拟合：分别在对齐、抓取前、闭合附近三个阶段，选择离训练样本中位数最近的示范框作为视觉子目标。对齐阶段沿用当前物体的表观大小。这个简单的阶段模板是后续学习模型的对照基线，不能验证视频生成能力或跨物体泛化；任务固定为抓取同一个物体，不接受任意任务文本。

输出：当前框和三个视觉子目标，以及对应的训练参考图路径。参考图来自示范，不是针对当前场景生成的未来图像。各阶段可以来自不同示范，连续性与物理可执行性没有验证。输出是少量关键帧目标，没有时间参数化或完整运动轨迹。

评估：在独立回合上计算中心像素误差与宽高平均绝对对数误差，同时报告始终保持初始框的基线。对数尺度误差是无量纲值，不是百分比。输出训练起始范围之外的提示，不将其解释为校准过的置信度。只比较视觉标注误差，不能据此报告真机抓取成功率。

## 数据格式与运行

复制 `examples/dataset.template.json` 后替换路径和示例数字。模板中图像不存在，数字仅演示格式。`frames` 可包含完整标注序列，也可仅包含上面的四帧；`keyframes` 使用该列表的零起始索引。添加独立的 `split: "test"` 回合才能评估。

- 图像相对路径以 JSON 所在目录为基准，也可使用绝对路径。
- `camera_id` 代表同一相机、安装、分辨率和裁剪设置；这些发生变化时需使用新标识并重新采集。
- `target_id` 代表同一个实体物体。本版不支持不同尺寸物体之间迁移。
- 所有回合图像尺寸须相同。工具检查路径与回合 ID 的训练/测试重叠，但无法识别复制改名的同一视频；采集者仍需保证独立划分。

```bash
python3 -m pip install -e '.[test]'
python3 -m imageplanner.cli validate /absolute/path/dataset.json
python3 -m imageplanner.cli fit /absolute/path/dataset.json --out outputs/model.json
python3 -m imageplanner.cli evaluate outputs/model.json /absolute/path/dataset.json --out outputs/evaluation.json
python3 -m imageplanner.cli plan outputs/model.json --bbox 200 140 40 40 --size 640 480 --camera-id wrist_fixed_mount_v1 --target-id object_01 --out outputs/plan.json
python3 -m pytest -q
```

`plan` 中的框与尺寸必须换成当前原图的实际数值。预测目标超出图像范围会拒绝输出。

如果系统自带 pytest 与已安装插件冲突，可用 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q` 运行本项目测试；项目本身不需要第三方 pytest 插件。当前环境使用该命令通过 5 项测试，覆盖坐标转换、留出评估、数据泄漏检查与相机设置检查，测试数据均为合成样本。

## 什么算本轮取得进展

先完成数据可读取、标注一致、回合独立划分；再看各阶段在留出回合上的误差是否优于保持初始框，并逐个检查失败案例。不能只看总平均值，也不能用测试集挑模板后仍将其称为独立测试。

如果视觉目标在同一安装和同一物体下已经不稳定，应先检查遮挡、透视、姿态和阶段定义。只有基线与数据问题明确后，才值得增加图像条件序列模型。真机闭环是后续独立实验。
