# 第二代手臂右手标定全流程

本文记录双臂 `dual_v2_2` 的右手（`armR`）固定棋盘格、固定相机的 `eye_to_hand` 标定流程，以及截至 2026-08-04 的实际标定与验证结果。

## 1. 标定目标与坐标约定

### 1.1 当前硬件布置

- 相机：固定在工作空间中，不随机器人运动。
- 棋盘格：刚性固定在右手/右臂末端。
- 标定模式：`eye_to_hand`。
- 机器人配置：`dual_v2_2`。
- 采集手臂：右臂 `armR`，索引为 `1`。
- 左臂 `armL`，索引为 `0`，采集时必须保持当前位置。

> 不要使用原始 `record_data.py` 做右手标定。它默认记录 `arm_index = 0` 的左臂位姿，会使图像中的右手棋盘格与保存的机器人位姿不对应。

### 1.2 变换含义

| 符号 | 含义 | 来源 |
|---|---|---|
| `T_base_ee` | 右臂末端坐标到机器人基座坐标的变换 | `ee_pose.csv` |
| `T_cam_board` | 棋盘格坐标到相机坐标的变换 | `solvePnP` / OpenCV 标定 |
| `T_base_cam` | 相机坐标到机器人基座坐标的变换 | `extrinsics.yaml` |
| `T_ee_board` | 棋盘格相对右臂末端的固定安装变换 | 验证脚本自动估计 |

尽管外参目录名为 `base_to_camera`，当前保存的 `extrinsics.yaml` 实际矩阵是 `T_base_cam`，即：

```text
p_base = R_base_cam * p_cam + t_base_cam
```

右手验证采用以下一致性公式：

```text
T_ee_board = inverse(T_base_ee) * T_base_cam * T_cam_board
```

不同姿态下推导出的 `T_ee_board` 越一致，说明外参越可靠。

### 1.3 单位

- `ee_pose.csv`：位置单位为米，姿态为 `[qw, qx, qy, qz]`。
- `extrinsics.yaml`：平移单位为米。
- `machine-readable results.json` 中的 `T`：平移单位为毫米。
- `0804-calib.txt` 当前第二组（右臂）关节值：单位为度。

## 3. UDP 与 Panel 配置

当前 `camera_calibration_cv/config.yaml` 为：

```yaml
receive_robot_state:
  enabled: true
  local_ip: "127.0.0.1"
  local_port: 30241
  remote_ip: "127.0.0.1"
  remote_port: 30240
```

Upper Software 的 Remote 页面应设置为：

```text
Local:  127.0.0.1:30240
Remote: 127.0.0.1:30241
```

映射关系：

| 方向 | 端口 |
|---|---|
| Panel 接收来自采集脚本的命令 | `30240` |
| Panel 向采集脚本发送状态 | `30241` |

在运行采集或验证脚本前：

1. 启动 `dual_v2_2_rt_control`；
2. 启动 `dual_v2_2_upper_software`；
3. 在 Upper Software 的 **Remote** 页面点击 `Connect`；
4. 再点击 `Start`。

若出现：

```text
No panel state received within 30s
```

优先检查 Remote 页面的 IP/端口及 `Connect`、`Start` 状态，而不是检查相机或棋盘格。

## 4. 采集前准备

### 4.1 固定棋盘格

1. 棋盘格必须固定在右手，采集全过程不可松动；
2. 相机必须固定，标定后不可移动；
3. 使棋盘在全部姿态下尽量完整、清晰地出现在画面内；
4. 避免反光、运动模糊、棋盘过度靠近图像边缘。

### 4.2 轨迹设计

建议采集 25–35 个姿态，最终保留至少 20 个有效样本。

姿态必须具有充分变化：

- 棋盘覆盖图像中心和四角；
- 具有 2–3 个不同距离；
- 绕多个轴旋转，单轴建议变化约 20–45°；
- 总体旋转范围建议不少于约 60°；
- 不要只做平移，或只绕单一轴旋转。

`0804-calib.txt` 每一行格式为：

```text
[left_arm_7_values], [right_arm_7_values]
```

右手标定脚本只使用第二组右臂数据，左臂会被持续锁定在实时当前位置。因此第一组数据的单位不影响右手标定运动，但不应使用原始通用采集脚本让左臂跟随这组数据。

### 4.3 棋盘格预检查

先检查相机和棋盘格识别：

```bash
python3 camera_calibration_cv/example/detect_chessboard.py
```

确认窗口中棋盘角点稳定、完整后按 `q` 退出。

## 5. 右手标定数据采集

运行：

```bash
python3 camera_calibration_cv/example/record_data_on_right_hand.py
```

该脚本会：

1. 读取 `example/0804-calib.txt`；
2. 只移动右臂 `armR`；
3. 持续将左臂命令更新为其当前关节位置；
4. 等待右臂到位且速度接近零；
5. 同步保存相机图像、右臂关节角和右臂 `ee_pose`；
6. 若目标超时或棋盘图像不可用，则跳过该样本。

### 5.1 采集输出

采集结果写入：

```text
calibration/session_0804/results/
├── 01.png
├── 02.png
├── ...
├── joint_position.csv
├── ee_pose.csv
└── records.csv
```

> 注意：`record_data_on_right_hand.py` 启动时会删除当前会话的 `results/` 目录。若需保留旧数据，应先备份或为新采集设置新的 `calibration_path`。

### 5.2 采集成功检查

采集结束后检查：

```bash
wc -l calibration/session_0804/results/ee_pose.csv
```

并确认：

- PNG 数量与 `ee_pose.csv` 数据行数量一致；
- `ee_pose.csv` 中是右臂而不是左臂的末端位姿；
- 右臂位姿在空间中有明显的平移和旋转变化；
- 左臂没有跟随轨迹移动。

## 6. 执行标定

运行：

```bash
python3 camera_calibration_cv/example/calibrate.py
```

脚本会：

1. 加载采集图像和 `ee_pose.csv`；
2. 检测棋盘格并求解相机内参；
3. 按重投影误差过滤离群图像；
4. 用右臂末端位姿和棋盘位姿求解 `eye_to_hand` 外参；
5. 保存结果。

### 6.1 当前误差阈值

当前 `calibrate.py` 使用：

```python
error_threshold = 0.15
```

此前的 `0.015` 对当前误差计算方式过严，会导致全部图像被过滤。该项目的误差计算不是标准像素 RMS，不能直接把 `0.015` 理解为 `0.015 px`。

若出现：

```text
Remaining valid images: 0
```

说明阈值过低或图像质量明显不足。应先检查单张图像质量和棋盘角点，再调整阈值；不要无条件把阈值设置得很高。

### 6.2 标定输出

```text
calibration/session_0804/base_to_camera/results/
├── intrinsics.yaml
├── extrinsics.yaml
├── machine-readable results.json
└── report.json
```

`calibrate.py` 当前保存 Daniilidis 方法的外参，同时终端会打印 Tsai、Park、Horaud、Andreff、Daniilidis 的结果。若多种方法差异很大，或出现：

```text
Not enough informative motions
```

则不能认为手眼外参有效，必须重新采集更大旋转范围的右臂姿态。

## 8. 外参独立验证

验证脚本：

```text
camera_calibration_cv/example/verify_calibration_on_right_hand.py
```

该脚本不会覆盖标定采集数据。它会：

1. 加载当前 `intrinsics.yaml`、`extrinsics.yaml` 与标定报告；
2. 自动检查保存外参和 `ee_pose` 的变换方向；
3. 回放一组验证右臂姿态；
4. 保存验证图像、右臂末端位姿和 PnP 棋盘位姿；
5. 计算各验证样本的 `T_ee_board` 与标定参考值的偏差；
6. 生成 `PASS` 或 `CHECK_REQUIRED`。

### 8.1 验证轨迹要求

验证轨迹必须使用**未参与标定**的新姿态。不要使用 `0804-calib.txt` 作为最终独立验证轨迹；它只能验证重复性，不能充分验证对新姿态的泛化能力。

验证文件格式与标定轨迹相同：

```text
[left_arm_7_values], [right_arm_7_values]
```

仅第二组右臂数据会被使用。

### 8.2 先执行安全 dry run

不带 `--execute` 不会移动机器人：

```bash
python3 camera_calibration_cv/example/verify_calibration_on_right_hand.py \
  --targets /绝对路径/右臂验证轨迹.txt \
  --right-target-unit deg
```

预期能看到：

```text
Selected transform convention: invert_saved_transform=False, invert_ee_pose=False
Calibration board-mount consistency: ...
Dry run completed. Add --execute to command the robot.
```

### 8.3 执行实际验证

确认 dry run 和轨迹安全后：

```bash
python3 camera_calibration_cv/example/verify_calibration_on_right_hand.py \
  --targets /绝对路径/右臂验证轨迹.txt \
  --right-target-unit deg \
  --execute
```

若右臂目标文件使用弧度，将参数改为：

```bash
--right-target-unit rad
```

验证输出目录示例：

```text
calibration/session_0804/validation/20260804_163750/
├── 01.png
├── ...
└── validation_report.json
```

### 8.4 当前验证结果

当前已执行一次重复性验证：

- 轨迹：`0804-calib.txt`（与标定轨迹相同，不属于独立验证）；
- 捕获样本：29 个；
- 中位平移误差：`3.92 mm`；
- 中位旋转误差：`1.53°`；
- 验证状态：`PASS`。

该结果说明外参在已知轨迹上的重复性较好，但不能替代新的未见姿态验证。

当前验证中部分样本 PnP 重投影误差达到 `5–7 px`，并导致最大旋转误差达到约 `25°`。这些通常是棋盘模糊、反光、角点质量差或视角不佳造成的离群帧。

建议：

- 优先保留 PnP 重投影误差小于约 `1–2 px` 的验证样本；
- 重新采集高误差验证姿态；
- 使用至少 3 个新的右臂姿态完成独立验证；
- 若独立验证仍稳定在约 `5–10 mm`、`< 3–5°`，则可认为当前外参具备较好的工程可用性。

## 9. 常见问题排查

### 9.1 `yaml-cpp ... bad conversion`

曾出现：

```text
yaml-cpp: error at line 20, column 33: bad conversion
```

原因是配置中数值拼写错误，例如：

```yaml
-6s0.0
```

应修正为：

```yaml
-60.0
```

YAML 会将错误数值当作字符串，后续 C++ 转换为 `float` 时失败。

### 9.2 `No panel state received within 30s`

检查：

1. RT Control 和 Upper Software 是否都在运行；
2. Remote 页面是否已 `Connect`；
3. Remote 页面是否已 `Start`；
4. 端口是否为 Panel Local `30240`、Panel Remote `30241`；
5. 标定 `config.yaml` 是否为脚本 Local `30241`、Script Remote `30240`。

### 9.3 `Not enough informative motions`

说明用于手眼标定的末端姿态变化不足。常见原因：

- 保存了左臂 `ee_pose`，但棋盘在右手；
- 全部姿态近似相同；
- 缺少多轴旋转；
- 只做平移。

解决方法：使用 `record_data_on_right_hand.py`，并重新采集具有较大平移和旋转范围的右臂姿态。

### 9.4 图像与位姿数量不一致

检查：

```bash
ls calibration/session_0804/results/*.png | wc -l
wc -l calibration/session_0804/results/ee_pose.csv
```

`ee_pose.csv` 比图像数量多 1 行是正常的，因为第一行是表头。

### 9.5 `PASS` 但存在大离群误差

验证脚本的默认判定使用中位误差阈值：

```text
中位平移误差 <= 20 mm
中位旋转误差 <= 5°
```

因此少量严重离群帧不会阻止 `PASS`。仍应查看 `validation_report.json` 中的：

```text
max_translation_error_mm
max_rotation_error_deg
pnp_reprojection_error_px
```

并对高质量要求任务重新采集或过滤坏帧。
