# V3.1 planner → Upper 指令发送（2026-10-12）

适用于 `dual_v2_2_upper_planner_v3_1.py`，包括使用该适配器的 V3.2–V3.4 抓取入口。原规划器和 Upper/RT 协议没有修改。

普通 MotionGen 新轨迹开始计算时，发送一次固定实测关节保持目标，保留上一条已发送夹爪目标（首次使用面板实测夹爪值）。保持目标只采样一次，不随反馈漂移。独立线程每 50 ms 重发；规划结果通过原检查后同步替换，防止异步排队破坏视觉伺服的接续时效。已有轨迹的正常执行不会每轮被切换成保持。

视觉伺服仍走 CPU differential servo 和 ExecutionGuard；独立高度监测、碰撞检查、目标有效期保持原规则。后台重复已提交的数据副本，不调用 CUDA、不生成新目标，也不更新视觉反馈时间戳。

边界：
- Upper 原 500 ms 断流锁停不变。
- 有效 PanelState 必须在 250 ms 内；重复读取不会刷新接收时间。
- 活动指令必须由主循环在 250 ms 内续期。主循环失活：有新鲜反馈时发一次实测保持，然后停止发送，交给 Upper 断流锁停。
- 普通规划期间仅固定保持可延长到 10 秒。到期结果不能恢复下发；需要排查超时并重新启动。
- Stop 清除缓存、使计算中的旧会话结果失效；不会后台自动按 Start。
- 规划完成时，比较实测关节与该次规划输入（不是后来采到的保持位置）。偏差超过 0.002 rad 时，只丢弃这一条未发送轨迹，保持原固定关节目标；新鲜反馈连续 150 ms 变化不超过 0.0005 rad 后，从新反馈重新规划。保留原请求目标，不重发已丢弃轨迹。最多拒绝 3 次，恢复总时限 10 秒；仍不稳定则保持后交给断流保护。
- 客户端发送 `book_v3_1_hold` 时，即使视觉伺服尚未建立历史指令，也由主循环持续维护固定保持；主循环失活或反馈断流仍会失效，不无限续期。
- SINGLE_POINT 保持使用 0.2 秒插值参数，避免继承 RAW 包的零插值时间。
- 发送间隔超过 200 ms 会打印 `V3.1 panel send gap`，便于定位调度停顿。

修改后需结束当前抓取轮次、重启适配器，再启动新的抓取轮次。没有自动重启进程或执行机械臂运动。

```bash
/mnt/ssd/robotarm/env/curobo/bin/python /mnt/ssd/user/V/dual_v2_2_control/cuarm_upper_planner/dual_v2_2_upper_planner_v3_1.py
```

离线验证：`dual_v2_2_agent/test_v3_panel_transport.py` 包含 800 ms 阻塞规划、后台保持、规划超时、活动指令过期、反馈丢失、Stop/Start 期间迟到结果、日志中的 0.003236 rad 起点漂移后恢复、持续不稳定超时、无视觉历史指令时的客户端保持、协议序列化、关闭时保持等测试；联合原 execution/direct servo/microsteps 回归。离线通过不等于已完成实机验证。
