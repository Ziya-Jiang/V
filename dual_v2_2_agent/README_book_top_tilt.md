# 单指贴书上沿与倾转：独立开发入口

更新（2026-10-13）：本文件下方保留最初几何原型的设计记录。后续独立程序已建立为 [cart_book_grasp_v4_1.py](/mnt/ssd/user/V/dual_v2_2_agent/cart_book_grasp_v4_1.py)，当前接线、标定要求与启动方式见 [V4.1说明](/mnt/ssd/user/V/dual_v2_2_agent/README_cart_book_grasp_v4_1.md)。新版本已接共享头部观测和普通CuRobo小路点，仍未实机验证；本文件旧“尚未接入”条目是原型阶段状态。

当前需求：右手夹爪左侧手指保持水平，使用较长的指腹下表面接近书上沿，把书朝机器人方向倾转约 45°；45°是期望值，不是必须压到的终点。当前只有图像与位姿，没有可用接触力反馈。本阶段不实现另一只手接抓，不修改现有 V3.4 抓取或其固定高度保护。

## 已实现与尚未实现

`book_top_tilt_geometry.py` 是离线几何内核，无机器人、相机、GPT 或网络 I/O，没有执行运动的入口。输入必须来自测量：支点/轴、书上沿接触点、单指接触点相对 TCP 的偏移及水平工具姿态。模块计算绕支轴的接触圆弧、补偿接触点偏移后的 TCP、从书的观测点计算倾角，以及依据实测角度限制的下一小步目标。默认工具姿态固定，不以腕部旋转角代替书的旋转角。13 项纯几何测试通过。

尚未接入：实时书上沿/支点跟踪、单指接触位置标定、纯视觉接触候选识别、允许 X/Z 联动的新控制模式、实机调试。因此现在没有可用于机械臂执行整轮动作的启动命令。

## 在线流程设计

1. 定位同一本书的上沿、下方支撑角/轴，以及右夹爪左侧手指实际接触部位。GPT 可给图像区域；三维距离仍由标定与实测深度计算。单个三维支点不足以确定转轴，需要支轴方向。
2. 将手指接触点对准上沿预接近点；图像目标是手指接触点与书上沿的相对误差，不再是书脊中线对齐相机中心。另一根手指的包络也需检查。
3. 小步近接，建立“可能接触”的视觉状态。图像重合不能证明接触力，也不能证明没有碰到邻书。这里不能设置“图像到位便强行压入”。
4. 给有限的小幅倾转试探，以书的实际角度变化、接触点相对滑移和书底位移判断是否跟随。观察不到书响应时，不累计继续推进的目标。
5. 跟随书的实测角度沿支轴圆弧更新指尖目标；默认手指水平。顶部会同时向机器人方向和下方移动。书底滑动、接触丢失、观测无效或控制受限时保持/中止，不能用少点后盲目前伸作为本动作备用。
6. 接近期望角度或达到可用空间界限后保持；最终交接另一只手另做状态确认。本轮不执行松手/撤指，因为书可能需要持续支撑。

## 控制接口核查

现有 `servor.py` 只允许 Y 与工具轴旋转，X/Z 固定；V3.1 直接伺服后端也明确拒绝离开固定 Z 平面的目标。本任务需要独立接触/倾转模式，保留关节与碰撞检查，不能通过关闭原高度保护直接复用。

底层 `PanelState` 定义了 `arm_joint_torque`，但当前抓取端 `get_current_state()` 未提供它。存在协议字段不代表现场有已校准的接触力；本任务按用户确认的“只有图像/位姿”设计。

夹爪 URDF 描述左右两个滑动指体和 mesh，未命名实际接触表面上的点；不能把滑动关节原点或旧整夹爪的 50mm 偏移当成本次接触点。用户已选定较长指腹下表面；仍需标定该面的 TCP 位姿、长度和宽度。

## 指腹面目标（用户补充）

接触对象是一个有面积的下表面，不是指尖点。新增 FingerPad，以实际测量的平面中心、法向、长轴、长宽及边缘余量描述；输出书上沿观测点到平面的有符号间隙和是否位于有效区域内。投影落在面内且间隙小仍不宣称力接触成立。名义圆弧使用选定的面内参考点，实机需要根据书的观测姿态和面内接触位置更新；若底部滑动或书上沿离开指腹，不能继续沿旧圆弧推进。长宽及偏移不能从测试中的60×12mm样例取值。
