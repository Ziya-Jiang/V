# 原 Agent 双机接线进展

截至本次验证，erazer → vlmdemo 的真实 RGB-D 传输和原 Agent 相机接口已接通；实体抓把未执行。

## 已验证的视觉链路

- erazer 使用 serial `CV2TC5100060` 的头部相机，848×530，5 FPS 设备采集，最多 2 Hz 对齐数据输出。
- 独立相机进程不启动底盘驾驶舱或机械臂驱动。临时服务 `cart-head-observer` 限制为一核 CPU 配额、1 GiB 内存和 600 秒采集；会自动退出。
- 从 vlmdemo 经 SSH 请求最新帧。源端按自己的 monotonic 时钟检查帧龄和 boot ID；接收端再加完整往返耗时作为帧龄上界，无需假设两台机器时钟同步。
- 保留原采集时间；校验相机序列号、配准标志、分辨率、哈希、请求 nonce、帧序号和来源重启标识。超过 1.5 秒的到达帧龄上界、重复帧、旧启动缓存均拒绝。
- 已完成 10 帧跨机传输，随后 5 帧通过原 `RobotRAM.controllor.extern_camera.OrbbecCamera` 的远程派生接口读取。未打开 vlmdemo 本机相机，未实例化 RobotArm。
- 接口输出 RGB + 毫米深度；相机在半身根下的平移恢复为 `[106.097, -3.549, 565.275]` mm。
- 实测传输往返约 0.23–1.01 秒（包含首次启动的旧协议样本）；加入服务就绪握手后，5 帧约 0.28–0.68 秒。该链路仅适合静止观察和分阶段定位，尚不用于快速闭环视觉伺服。

在 vlmdemo 上重新观察：

```bash
cd /mnt/ssd/user/V/dual_v2_2_agent/cart_grasp
bash run_observe_erazer.sh --count 5
```

首次 SSH 连接可能询问 erazer 的密码；密码不存入脚本。机器人 USB 重插后若权限丢失，需要重新确认相机节点权限。不要与另一套占用同一相机的 SDK 采集并行启动。

## 当前感知结果

画面中推车距离较近，部分车体被白色板件遮挡/图像边界截断。5 次检查均以“把手不平行”或“间距不符合测量车体”拒绝。

原 CuRobo 工厂的离线测试脚本 `tools/probe_original_planner.py` 因同一感知检查失败，在建立运动规划器之前退出。没有放宽阈值，没有把历史车把位置代入当前抓取。脚本若后续运行，仍使用明确标注的历史关节记录，结果不可执行。

## 控制链路

erazer 当前只有 8780 网页服务在线，RT 未启动，无新鲜关节反馈，未接管。该网页接口不是原生上位机的 Remote UDP 接口。

原生上位机接收端增加 500 ms 断流停止：收到过有效命令后超时会切回实测关节/手爪位置、进入 STOP，需要手动 Start；积压的过期包不能刷新心跳，恢复网络不自动恢复动作。修复过程中还发现原停止函数依赖缓存的控制模式，初始模式未切换时可能给位置关节填零，已改用实际 `PanelCommand.target_type`。

修改位于 vlmdemo 原项目的 `cuarm_upper_software/src/panel/remote_page_widget.{h,cpp}` 和新头文件 `remote_command_lease.h`，旧源码和二进制备份在 `cart_grasp/runtime/backups/`。原生上位机已在一核 CPU 配额下重编译。测试不启动 MainWindow 或 RT，不调用任何机器人驱动。

验证结果：21 项 Python 报文/相机测试通过；独立 C++ lease 测试通过；链接真实上位机对象的 Qt 集成测试通过，覆盖 550 ms 断流后保持全部 14 关节与手爪反馈位置、进入 STOP、新包不能自动恢复、过期队列拒绝。该测试只在进程内注入模拟数据，PanelState 只发往本机测试端口，未运行 RT，不能代替实体停止距离和制动验证。测试已结束，GPU 0 验证后为 0% 使用率。

机械臂实体执行仍需要：恢复手爪设备和当前关节反馈、确认使用哪套上位机/RT协议与标定、当前推车完整定位、包含环境的整段路径及接触阶段验证。原生 RT 二进制早于源码，且 erazer 的原生依赖还未部署，不可直接拿来替换已调试的 Seldon RT。
