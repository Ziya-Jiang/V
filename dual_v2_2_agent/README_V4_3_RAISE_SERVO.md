# V4.3：自适应抬升伺服与先抬升后复位

从V4.2独立派生，V4.2原行为保留。复用V3.4/V1_3感知、循环和按键，以及独立V4.1后端；未新建规划器或更换UDP端口。规划动作继续使用book_v42_raise_servo以复用既有右臂fixed-X路径检查，后端日志出现V4.2是该兼容协议名称。

## 运行

先使用已更新的独立V4.1规划器，再运行客户端：

```bash
/mnt/ssd/robotarm/env/robotram_wx/bin/python /mnt/ssd/user/V/dual_v2_2_agent/cuart_book_grasp_v4_3.py --execute
```

别名cuart_book_grasp_v4.3.py和cuart_book_grasp_v4-3.py进入同一程序。`--check-config`仅检查配置，不连接设备。默认使用cuart_book_grasp_v4_3_config.json及独立距离配置。

## 提速行为

- gain保持0.5；已居中连续2个控制周期且离终点超过20mm，最大平移步长从10增加到15mm。
- 当前图像误差比率为max(|水平误差|/3px,|角误差|/1.5°)。误差回到1以内允许抬升；随后轻微偏出时仍可边升边纠偏，进度随误差减小；达到2暂停抬升，回到1内恢复。小于到位容差的进度不发送，避免无效小步。
- 剩余20mm内最大步长5mm；点耗尽后历史接续仍最多10mm、近端5mm，不使用15mm加速。终点验收仍3px/1.5°及原高度容差。
- 极短终点进度使用0.5mm位置到位要求，避免3mm到位球吞掉最后小步。
- 仍为分段规划、到位后更新控制；不是运动中连续重发关节目标，不承诺硬件频率或提速倍数。

参数在cart_book_grasp_v4_3_raise.json，每次抬升开始读取。所有X漂移、路径预算、关节/碰撞、真实反馈过期保护保留。

## 初始丢点与跟踪恢复

初始化选区成功后，必须在连续3张不同时间戳的新图上通过真实特征跟踪，才进入抬升控制。GPT返回前的图像只能作参考，不直接作为当前测量，也不把旧选区直接套到新图上。

点数不足且有效抬升历史不满10mm时，不再立即结束整轮：停止新增运动目标、关闭单一采集线程、通过连续静止反馈确认停稳，再采新图让GPT复核同一本书并重建跟踪。恢复也需连续3张新图有效；特征不足或几何跟踪验证失败可重试，整个抬升最多3次GPT恢复（包括初始化恢复），不重置时间、路径预算或初始位置锚点。新参考建立后丢弃旧Jacobian和历史方向，重新观测/辨识。

已有充分可信历史时仍可按原历史方向接续。真实反馈过期、位姿越界、无法停稳、相机失效或同书身份未确认仍停止；不能以恢复为由忽略这些错误。每次恢复记录于gpt_centerline_recovery_XX/recovery.json；事件日志保留丢点数和历史跨度。V4.2及共享恢复模块未修改。

## 复位顺序

复位前保持当前实测关节，沿基座+Z从保持后的实际TCP抬升50mm，两段各25mm；命令X/Y和姿态保持。每段使用规划器及新鲜连续稳定到位反馈，并复核实测位置3mm/姿态1°。完成后才发first_reset。

- 新一轮（包括失败后回车）识别前复位经过此流程。
- 按p：先保持并抬升50mm，再沿用松爪、first_reset，随后等待回车；抬升失败不松爪、不复位，并尝试保持。
- 已在准备关节位1°范围内跳过重复抬升，沿用原复位逻辑。
- s仍沿用停止后续循环的语义；异常不自动启动复位。

cart_book_grasp_v4_3_reset.json在每次复位请求时热加载：lift_mm=50、step_mm=25。抬升仍必须通过规划/实测检查，不能保证任意姿态都能抬升50mm。读取过期反馈时不发送抬升指令。
