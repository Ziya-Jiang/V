## 0. 阅读约定与证据边界

这段研发中，需求改变过多次，配置和 README 也可能保留旧模式。本文按“当时的目的—现象—原因—采取的策略—验证范围”整理，不能把某一旧版本的参数当作当前全系统参数。

证据分为四类：

- **现场日志**：用户粘贴的真实运行输出，能证明当次发生过的动作、反馈或失败；没有日志的环节不补写成功。
- **保存图像回放**：真实相机图片上的离线感知实验，不能推导整轮控制成功率。
- **代码／配置及模拟测试**：确认实现存在、接口或状态机通过测试；简化动力学不等于真实机器人。
- **待验证策略**：由问题提出、需后续实机验证的设计或假设。

对不能从现存记录确定的原因，明确写为“可能原因／待查”。部分早期对话只有用户需求和报错，没有完整修改记录，因此不臆造每次修复的精确日期、提交号或成功结果。标有日期的实验目录可作为当时证据；目录日期不一定等于每次代码修改日期。

本文不保存 API 密钥内容。API 文件路径仅作部署线索，不作为论文公开附件。

## 1. 研发主线与需求演变

最初目标是：保留已经有的抓书粗定位和抓取流程，在最后接近书脊时增加腕部视觉闭环，使手的位置不完全依赖一次性头部定位和固定前伸量。

演进可分为九个阶段：

1. **基础几何**：标定腕部单目相机，确认头部 RGB-D 手眼、URDF 末端和指尖偏置。
2. **示教终点**：在 V1_3 上加入 V3；先 Y/Z 对准，再尝试前伸期间 XYZ 图像闭环，终点用最终抓取示教图定义。
3. **跨视角身份交接**：尝试 SIFT、XFeat、SuperPoint + LightGlue 验证头部选中的书与腕部书一致；提高头部分辨率。
4. **改为几何目标**：接受“粗 Y 对准后，腕部中心书就是头部目标”的假设，放弃必须同书纹理匹配；图像管对准，V1_3 深度管 X 终点。
5. **简化控制任务**：CoTracker Y/Z → 快速书脊中心列 → 中线 Y／工具轴旋转；Z 固定，不要求书上下完整入镜。
6. **连续控制**：逐步规划和停稳检查太慢，独立 V3.1 先尝试滚动轨迹，随后只把视觉阶段换成 CPU 差分伺服，普通动作继续 CuRobo。
7. **稳定与恢复**：处理时间戳、旧目标、ACK、轨迹接续、高度漂移、RAW 滤波、振荡、丢点后锁姿等；V3.2 统一恢复参考。
8. **感知增强和通用化**：V3.3 最高原始分辨率；V3.4 书脊区域和 GPT 恢复；安装抓取特征 Skill，独立 `servor.py` 服务通用物体。
9. **车把任务**：用打印 ArUco 表达目标身份和方向；头部 GPT 区域定位 + 实测深度粗定位，腕部 ArUco + Image Jacobian 前伸纠偏，夹取、保持、松开、撤回和返回。

贯穿全程的另一个分支是 **三维工作空间／头部 AR 可视化** 和 **RGB-D 共享服务**。它们用于解释几何和观察状态，并非运动控制成功的替代证据。

## 2. 相机标定、参考系与终点定义

### P01：腕部相机未标定，像素误差无法保持一致

最初使用一块“12×9，每格 1 cm”的棋盘，要求用成熟工具快速完成 `camera_calibration`。这里的 12×9 是格子数还是内角点数，需要在复现实验时核对实物；如果是格子数，内角点数应另行计算，不能直接把描述抄进标定命令。

用户提供的单目 pinhole 标定分辨率为 1280×720：

```text
K = [[683.0351877157348, 0, 629.9780030679196],
     [0, 689.4064870396259, 418.9316595398111],
     [0, 0, 1]]
D = [-0.28024828685428893, 0.05953061708134112,
     -0.0033341681831325514, 0.0022132051564490575, 0]
R = I
P = [[468.222331813079, 0, 637.4404354643108, 0],
     [0, 626.4484097000374, 428.2366255473854, 0],
     [0, 0, 1, 0]]
```

标定归档原先为 `/tmp/calibrationdata.tar.gz`，项目中现有 [calibrationdata.tar.gz](../calibrationdata.tar.gz)。V3 说明记录采用 `initUndistortRectifyMap(K,D,I,K,size)`，保留 K 和原尺寸，不裁剪。这意味着控制中的去畸变像素不能直接与 P 对应图像或原始畸变图混用。

**经验**：保存标定数值还不够；应一起保存分辨率、去畸变约定、图像所属坐标系、相机和标定文件指纹。现有日志没有提供本次标定完整重投影误差分布，论文不能自行补出标定精度。

### P02：把观测位置误当成最终示教位置

用户明确澄清：拍下的中央浅色书脊图是“闭合即可抓到书”的最终示教图；之后机械臂已退回第二段前伸前的观测位置。

最终图与观测图保存线索：

- [最终示教图](../RobotRAM/output/v3_reference_current_20261009.png)
- [退回后的观测图](../RobotRAM/output/v3_observation_before_stage2_20261009.png)

初期 XYZ 方案将最终图中四个固定平面点作为目标，经当前图纹理匹配和单应性寻找对应点。原 README 记录两张实拍图有 12/16 内点、约 0.53 px 拟合 RMS，但四点到目标仍相差约 263–402 px。

**解释**：0.53 px 是模型对匹配点的拟合残差，不是闭环已经收敛，更不是机械臂抓取精度。

### P03：更换书本后，原示教图不再有对应纹理

用户询问书的颜色不同、不是同一本书时怎么办。最终图纹理天然绑定特定物体，不能因“都叫书”就共享像素点身份。

策略逐步从“恢复某张图”改为“恢复任务相关几何”：书脊中心线对准、工具方向对齐、深度决定前伸终点。这样减少重新示教，但必须承认后来的几何终点与早期最终图终点不是同一种任务定义。

### P04：URDF 第七轴、法兰、末端和指尖不是同一个参考点

曾专门检查右手法兰长度、第七轴与末端坐标系并制作三维可视化。证据入口为 [腕部坐标系可视化](../RobotRAM/output/right_wrist_frames_20261010/preview.html)。本会话现存文本不足以安全重述一个唯一“法兰长度”，不在此补写数值；论文应从指定 URDF 的 joint origin、工具偏置和机械图中重新明确所量的两点。

后续控制统一强调：基座 X/Y/Z、相机光轴、工具轴、`arm_end_effector_r` 原点、TCP 以及指尖各有含义。前伸采用基座 +X；实际指尖偏移需投影到该轴，不能把相机深度直接当作基座 X。

## 3. V1_3 基线和初期 V3：先解决反馈，再谈视觉闭环

### P05：控制器说运动完成，但粗前伸到位检查失败

典型报错：`ServoError: First-stage waypoint was not reached`。后续日志增加目标、实测、各轴差值、位置／姿态误差与稳定样本数。

粗前伸使用独立 8 mm 到位标准、1° 姿态标准，并等待新鲜连续稳定反馈。现场后续能看到 0.567、0.700、0.430 mm 等粗前伸误差通过。

**经验**：规划器结束、面板结束和真实末端到位是三件不同的事；粗动作与 2–5 mm 视觉小步也不能共享过宽的 30 mm 标准。

### P06：第一版“只 Y/Z 对准后固定前伸”仍有累积误差

用户希望前伸过程也能看图修正，不只是先对准再补一个固定偏移。

早期最终图方案尝试基座 XYZ 的实测局部图像雅可比：四个图像点组成 8 维特征，使用 XYZ 探测拟合 8×3 矩阵，阻尼最小二乘输出小步。它避免在腕部手眼变换不完整时，直接把相机速度当作基座速度；但仍是“停稳—拍照—纠偏”，并未因此成为连续高频伺服。

## 4. 头腕匹配：从强身份验证到明确的场景假设

### P07：头部选书区域太小、纹理不足，阻断第二段

多次出现：`Selected book has too little visible texture for V3 tracking`。

一个关键现场：`features=9/16, mask_bbox_px=23x92, mask_pixels=1111, interior_pixels=665`。它表明头部选中区域在掩码收缩后仅剩很少纹理。程序没有进入预期腕部闭环，并不一定是机械臂运动失败。

策略：在身份校验前保存头部原图、选中掩码、腕部采集图和诊断数据；分清“头部身份入口失败”与“腕部初始化失败”；查清在线入口是否仍调用旧 SIFT 阈值。

### P08：尝试 XFeat，并与原方法比较

进行了稀疏、半稠密、多尺度、ROI、可用匹配器组合等离线探索；使用正对照已知变换与负对照书本，不能只看连线漂亮与否。

证据：[XFeat 报告](../RobotRAM/output/v3_xfeat_comparison_20261009/report.json)、[页面](../RobotRAM/output/v3_xfeat_comparison_20261009/index.html)、[补充报告](../RobotRAM/output/v3_xfeat_comparison_extra_20261009/report.json)。

首批 head_to_current 的 SIFT 与 XFeat 多个路径仅有 0–1 对匹配，不足以支持单应性。报告明确：部分头腕图不同时间采集，没有同步身份真值；CPU 单次耗时不能直接当实时基准。

**结论范围**：不能写“XFeat 解决了头腕匹配”，也不能由少量失败样本断言方法本身无效。图像尺度、真实共同纹理、视角、目标面积和遮挡是关键限制。

### P09：尝试 SuperPoint + LightGlue，仍需区分识别与控制几何

证据：[SuperPoint 对比](../RobotRAM/output/v3_superpoint_comparison_20261010/index.html)、[原始报告](../RobotRAM/output/v3_superpoint_comparison_20261010/report.json)。

后续把旧头部 SIFT 初始化门槛从身份入口移开，使用 SuperPoint + LightGlue，但保留内点分布、投影有效性和控制点支撑。一个真实失败图回放中，全图 0 对、ROI 3 对，仍不足 6 对；已知变换正对照则可得到大量内点。

“6 个内点、内点率 ≥0.65、RMS ≤1.5 px”等宽松条件曾用于单帧身份候选接受。**接受单帧同书候选不等于控制点能可靠映射，更不等于可直接运动。**

### P10：提高头部 Orbbec 分辨率

头部旧消费者为 848×530；设备枚举得到最大彩色 profile 为 1280×800，10 FPS，MJPG。对原始最高分辨率采集的实验记录见 [summary.json](../RobotRAM/output/v3_head_max_observation_20261010/summary.json)。

该报告中同候选最佳内点数：浅色书 0→5、红书 0→6、深色书 9→7（848×530 → 1280×800）。宽松单帧身份通过 1 项，严格几何通过 0 项。这说明真实分辨率可能有帮助，但并非每本书单调改善，也尚未证明跨视角控制可用。

采集主机时差约 11–37 ms 的后续数据，也不能写成曝光级硬件同步。旧批次更有约 1.07 秒间隔，应分别说明。

### P11：为什么后来取消头腕匹配

用户曾要求必须验证两端是同一本书，后又明确改为“直接用腕部眼前最靠近中心的书”。其后确定场景假设：V1_3 已沿 Y 粗对齐，腕部中心书应是头部选中的深度目标，只能基于此假设继续。

因此取消跨视角身份入口是**任务约束的主动修改**，不是匹配算法被证明完全解决。论文必须报告这一假设：初始粗定位错误、相邻书间距小或遮挡时，几何对准可能对错目标。

## 5. CoTracker＋距离终点：任务解耦及遇到的问题

### P12：用当前书的跟踪点，替代原书最终示教纹理

讨论过 TrackAnything，后来采用 CoTracker 思路：在当前书可见中部初始化固定身份点，保持跟踪区域居中；不要求跟踪点来自原示教书。点数示例为 8，最低可见 6。

前伸终点改为 V1_3 的真实深度几何：

```text
x_goal = x_surface + insertion − fingertip_offset × (−R_tool[0,2])
```

历史配置的指尖偏移为 50 mm、伸入量为 100 mm。头部给基座 X 深度，图像闭环纠正 Y/Z；视觉中心不提供唯一接触深度。

### P13：第二段和总路程预算不足

`V1_3 endpoint exceeds remaining CoTracker travel budget`：例中起点 X≈518.55 mm，终点≈731.41 mm，第二段约 212.86 mm，超过原预算。

用户要求让第二段预算覆盖距离并同步总路程，后出现 `max_forward_mm=250`、`max_path_mm=400`。预算必须包含探测和纠偏，不能把一维净前进量当累计路径。

### P14：2 mm 指令被吞掉，容差却要求 1 mm

典型反馈：目标 Y 从约 38.4 到 36.4 mm，但实测仍约 38.389 mm，误差 1.984 mm；控制器直接报告结束。

检查发现旧规划器目标变化判定约 5 mm，小于此量的微步可能被当重复目标。修复方向是给 `book_v3_xyz_servo` 专用的微步目标变化判定及到位标准，原说明记录目标变化判定降低到 0.01 mm。客户端增加新鲜反馈、不同时间戳、连续稳定样本。

后来到位阈值按用户要求从 1 mm 调整为 2 mm，再在 V3.2 的相关客户端／后端同步为 3 mm。**不能把阈值加大当作被吞指令的根本修复**；初始微小探测仍需获得足够真实位移，才有可辨识的 Jacobian。

### P15：采图子进程 0.5 秒超时，阻断伺服

错误包括 `--capture-worker ... timed out after 0.5 seconds`。每次启动 Python、打开 USB、预热并取图，开销远超过只运行图像算法。

策略：腕部相机独立常驻采集，持有设备、持续排空缓冲，使用请求序号、捕获时间和帧年龄校验；减少重复启动和重复丢帧。超时仍中止，不用旧图继续发运动目标。相机读帧时戳不是硬件曝光时戳。

### P16：点几何不一致

`CoTracker point geometry inconsistent` 表示同组点不再支持预期刚性／局部平面几何。可能来源于遮挡、误跟踪、不同表面、视角尺度变化；仅靠该错误不能确定唯一原因。

策略：保留可见点数、几何一致性和模型残差检查，输出失败帧；不为“继续跑”直接取消身份／几何校验。后续改用更贴合书脊任务的中心线及局部纹理传播。

### P17：X 区间误报与实测／命令起点混用

`Measured/commanded X outside approach interval` 曾在 Y 探测后出现，X 的微小反馈偏差引发区间问题。

策略：以实际反馈定义阶段起点；Y/Z 探测返回不强行把 X 拉回旧命令值；区分测量容差和授权目标范围，使用新鲜 X 防止旧图目标回退。保留实际越界停止。

### P18：Y/Z 20 mm 纠偏范围耗尽

`Y/Z travel bound exceeded` 并非机器人已到关节极限，而是相对观测起点的软件范围已用尽；下一步 5 mm 可能越界。

用户提出无需此限制。演进重点是减少无关任务维度：不再追逐书脊上下中心，固定 Z，只对准水平中心和方向。后续不同模式仍分别有范围／路径／时间约束；不能将当时讨论概括成“全部限制取消”。

### P19：只加 gain／步长不能解释变慢

尝试过 `max_step_mm` 调整，配置还出现重复键 `20.0` 与 `5.0`。标准 JSON 解析通常只保留后者，容易误以为前者生效；超出校验范围又会报 `Invalid CoTracker setting: max_step_mm`。

速度应拆成采图、模型、规划、下发、实际执行、停稳、到位确认。减少逐帧可视化，后来设为每 200 帧一张，是降低额外开销的一项措施，而不是保证控制频率的充分条件。

## 6. 从点重心到书脊中心线

### P20：不关心上下位置，却让 Z 一直追图像中心

用户明确任务：粗到位后，书无论是否完整入镜，快速找书脊中心列；只希望手部相机水平对准书脊，不关心上下像素。

因此目标由二维中心 `(u,v)` 改为中心列 `u`，Z 固定。随后又增加倾斜书要求，变成 **Y 平移＋工具轴旋转** 对准中心线，X 仍由深度决定。

### P21：书倾斜，特征点均值不是书脊中心

如果整书 mask 包含斜视可见封面，特征点重心会向封面偏，现场表现为中心／中线偏向右侧。根本问题是几何目标定义错了，而非单纯跟踪点不够。

策略：区分整书与书脊；中线来自左右书脊边界的中点拟合；纹理点只负责传播该中线，不能用点平均坐标重新定义抓取中心。左右哪边是封面不能硬编码。

### P22：直接跟边界还是保留特征点

用户曾要求直接跟踪边界和中线，避免耗时特征点；后又要求恢复原特征点，点不足时改距离控制。最终主线使用 Shi–Tomasi／LK 光流、RANSAC 几何传播；**这时默认不再是 CoTracker**。旧 CoTracker 作为 legacy 模式保留。

初始化可有 80 个点，可靠点少于 6 时切换。点应位于书脊内部，避免光流窗口跨进封面和背景。书脊中线与用于跟踪的点集是两个对象。

### P23：靠近时丢点／几何共识失败

典型错误：`Centerline tracking lost reliable points`、`Centerline geometry lacks consensus`。

用户授权的书本方案：点少于阈值后退出视觉纠偏，锁定 Y、原始 Z 和完整姿态，按本轮 X 深度终点完成前伸。必须输出 `visual_alignment_verified=false`，不能称为全程视觉闭环成功。

后续 V3.4 对“几何共识失败”另有 GPT 重识别恢复，见后文；它和普通“点少于 6”不是同一分支。车把模式也不继承书本的丢点盲前伸。

## 7. V3.1：连续目标更新与规划器重构

### P24：每轮运动都完整规划、停稳和检验，运行缓慢

原循环为“图像→纠偏目标→MotionGen→执行→稳定确认→下一帧”。日志中的 `stable_samples=3/3`、约 0.2 秒稳定等待，只是总延迟的一部分。连续控制改成运动中消费新图和反馈、更新有限目标；探测和最终完成仍保留明确确认。

用户要求原规划器不要改坏、独立写新规划器。由此建立 `cuart_book_grasp_v3_1.py` 与独立 `dual_v2_2_upper_planner_v3_1.py`，后续按动作路由。历史上最初确实在旧规划器上加过视觉微步修复，不能把整个研发史写成“从未修改任何旧代码”；新架构的目标是隔离后续改动。

### P25：FK 缓冲批次冲突，状态发送线程崩溃

现场堆栈在 `_curobo_state_sending_task → _update_curobo_state → _compute_fk_without_lock → get_link_poses`：

```text
Target sizes: [1, 3]. Tensor sizes: [4, 3]
```

状态线程死亡后，客户端只看到 `No robot state received`、`first_reset 失败` 或配对恢复超时。它们并非没有识别到书的根本原因。

修复思路：隔离／同步可变运动学缓冲、保证 FK 输入输出 batch 一致；后续直接伺服使用独立 CPU 运动学，并做 CPU/GPU FK 对照。该堆栈直接证明形状冲突，具体哪条并发调用覆盖了缓冲须结合源码或复现确认，不能仅凭错误断言唯一竞争位置。

### P26：Python／NumPy 接口错误导致规划器退出

两个明确的软件接口故障：

- `AttributeError: 'list' object has no attribute 'tolist'`，位于重规划使用夹爪关节值的路径；应统一输入类型，不假设反馈永远是 ndarray。
- `TypeError: iteration over a 0-d array`，`arm_waypoint_dt=array(0.2,dtype=float32)` 在 UDP 序列化时被当可遍历值；应转换为协议接受的标量，测试真实打包路径。

**经验**：只通过数学函数测试不足以证明能下发运动；需要覆盖真实状态结构、异常分支、序列化、进程退出和正常关闭路径。

### P27：旧规划器／多个进程与无反馈

曾要求结束旧规划器进程。新旧进程共用真实面板，不能同时控制；客户端连错实例、适配器退出、状态线程死亡都可能表现为无状态或 ACK 超时。

策略：独立端口／启动指纹检查，明确 agent 10175、planner 10176；一次只有一个面板控制者，查真实进程与反馈，不用静态缓存冒充在线。`first_reset` 失败后取消识别，是上游未就绪，不能解释成模型漏检。

### P28：图像时戳没有对应位姿

报错：`PoseNotBracketed: V3.1 frame timestamp has no bracketing feedback`。

策略：保留位姿时间线，用图像时戳前后的反馈插值；临时没有配对时暂停更新运动目标，等待反馈恢复并重新采集新图，持续超时才退出。不能把等待新图期间真实发生的运动，混同于同一图像的配对误差。

配对中的时戳仍为主机侧获取／源反馈时戳，不能自动等同于曝光与编码器硬件同步。反馈进程已退出时，恢复策略也无法制造新状态。

### P29：运动中配对支撑过宽

现场：`pose pair support too wide: 6.271mm, 0.193deg, gap=0.0214s`。

即使时间间隔仅 21.4 ms，空间支撑仍可能超限。问题需检查时戳来源、状态新鲜度、速度、插值支撑与相机缓存；用户明确不接受只调大 3 mm 限制。策略是重采与恢复，保留精度准入，而非硬放行。

### P30：ACK 超时并不总是 IK 或碰撞失败

出现过 `planner acknowledgement timeout`、`status=4,target_matches=False`。

另一次适配器日志显示高度、碰撞检查通过，但多次 `panel path validation start expired; discard and replan from fresh feedback`，连续重试至第 4 次才接受。此时是验算和接续导致确认晚，不是视觉端能仅凭超时断言碰撞。

策略：ACK 绑定实际下发请求副本、区分收到／规划／下发／执行，记录请求身份、目标匹配和各阶段耗时。被缩短的分段终点与原完整请求要分开表示，不能简单按浮点目标相等推断一切。

### P31：放大 gain 和步长后，高度路径不合格

用户曾要求 gain>1、步长>1 cm，后要求 gain=5、步长100 mm，甚至不设前瞻上限。规划日志显示，一次约100 mm前伸时预测 Z 最大偏差4.401 mm，超过4 mm。

这是规划轨迹的中间路径问题，不是目标 Z 没固定。策略是超限后缩短目标距离并重规划；仅缩短轨迹时间不会让空间路径自动变直。

### P32：时间缩放的语义不能猜

用户先要求时间缩放1，后改0.9。当时记录 `waypoints_dt≈0.222222s`，对应部分有效轨迹时长约1.111s；后续另有1.333s日志，取决于发送路点及时间约定，不能脱离协议只数数组元素。

在该 CuRobo 时间参数语义下，0.9 不是简单“总时长乘0.9”；必须对照实际输出 dt。最终直接视觉伺服不再使用旧 `time_dilation_factor=0.9`；普通 CuRobo 动作仍有自己的时间参数。

### P33：规划高度通过，实测仍下沉

现场固定 Z：参考−10.951 mm，实际−15.522 mm，偏差−4.571 mm，超过4 mm。

关联规划日志：完整前伸到663.565 mm时预测 Z偏差10.720 mm被拒；缩至0.5后2.747 mm通过。随后目标又回到X≈495.727 mm附近纠偏，再尝试前伸；后续缩至0.25、3.423 mm通过。实际反馈却先前进再退，最终下沉。

**判断**：日志表明前伸／纠偏切换、在途运动与新目标接续存在不一致；轨迹采样通过不覆盖真实跟踪误差和面板插值。不能唯一归因于相机或某个 gain。

策略：

1. 纠偏目标以最新反馈构造，不把旧图 X 当成要退回的位置。
2. 处理轨迹接续状态，避免起点在规划期间已经失效。
3. 将4 mm总高度范围拆分出规划范围和跟踪余量，曾使用2 mm预测范围＋2 mm余量。
4. 独立监测实测 Z，固定参考不可被新目标或故障保持悄悄重设。
5. 普通保持和故障取消分开。

### P34：轨迹接续校验成本引发反复重规划

为了检查真实面板行为，曾对0、20、40 ms延迟进行 panel path 验证；虽然预测Z约0.18–0.54 mm、低于2 mm，但验证结束时起点过期，重新计算。

这是“检查更多却使结果更晚”的系统性问题。保留接续一致性要求，但不应靠无限延长ACK或无限重复规划解决。最终选择只将视觉阶段替换为局部直接伺服。

## 8. 仅视觉阶段使用 CPU 差分伺服

### P35：用户要求不用 CuRobo 反复规划视觉小步

明确范围是“只替换视觉伺服”。现有架构：

- 复位、粗定位、普通抓取后续动作仍走 CuRobo。
- `book_v3_xyz_servo`／`book_v3_1_stream` 走 CPU FK、数值机械臂 Jacobian、阻尼最小二乘。
- 输出经速度、加速度、关节领先量限制后的 RAW 关节位置，而不是直接向电机发送无约束速度。
- 同一适配器统一持有面板UDP，避免两个控制器争用。

视觉图像 Jacobian 与机械臂 Jacobian 是不同层次：前者从图像误差生成TCP修正，后者把TCP误差变成关节增量。不能将两者混写为一个矩阵。

### P36：直接伺服仍报 `PLANNING_FAILED`

客户端沿用旧状态枚举，可能把直接伺服内部拒绝统一显示为 planner/IK/collision failure。实际适配器输出曾是：

`Direct servo predicted Z path outside tracking reserve`

这时视觉阶段日志已经写明 `MotionGen bypassed`，不能再说是 CuRobo 求解失败。应读取适配器具体原因，并把通用状态映射与具体故障来源分开记录。

### P37：差分步的预测高度超限

策略：对最新反馈到候选关节指令的完整领先量进行整体缩放，1/2、1/4直至最小1/128；选合格路径后再碰撞检查。不能逐关节独立截断，破坏共同保持TCP高度的运动配合。

缩步后清除被拒增量的速度积分；仍无可行步时有限时间保持／恢复，持续失败停止。独立高度监测保留，恢复指向本轮原始Z，而不是漂移后的Z。

### P38：50 Hz 下仍很慢——底层 RAW 有滤波和斜坡

检查发现，RAW 仍经过2 Hz低通滤波，并有默认5秒目标追赶斜坡。提高外层 gain 或把前瞻设成无限，不能绕过这些执行层限制。

只对视觉RAW将目标时间设为0，避开旧时间斜坡分支；速度比例设为0.3。后端标称周期0.02秒（50 Hz）、TCP平移上限0.05 m/s（50 mm/s）、角速度0.15 rad/s、关节速度0.35 rad/s、加速度1 rad/s²、关节领先0.025 rad。

这些是设定上限，不是实测持续控制频率或实际速度。视觉外环最多10 Hz，与后端50 Hz、相机FPS、低层控制频率分别定义。

### P39：解除瓶颈后 gain=5 造成振荡

此前慢执行掩盖了高增益；去掉5秒斜坡后，实机记录出现明显Y振荡、累计路径预算耗尽。增益后来降低到0.6；V3.4连续外环进一步到0.35。

离线闭环用现场图像 Jacobian、真实RAW滤波及简化延迟关节模型，复现高gain消耗路径预算；降低gain可完成模拟任务。它支持该机制解释，但不是完整实机成功证明。

### P40：丢点切换后 `no measured progress`／`direct-mode pose drift`

现场有到X≈620 mm后丢点、保持到位，但随后无进展；也有X≈555.7 mm丢点后直接模式漂移。

若“锁定参考”“保持目标”“保持后的实测位置”“后续检查参考”分别取自不同时间，正常跟踪误差可能使相邻状态互相矛盾。只修改最终位置阈值不足以解决模式切换。

V3.2策略：一次锁定Y、完整三维姿态和本轮原始Z；超过恢复阈值先暂停增加X目标并纠正；退出恢复需多个不同时间戳稳定反馈。完整旋转误差用旋转矩阵，不只看roll，避免欧拉角跨±180°假异常。

### P41：高度恢复、目标断流和最终到位的边界不同

后端独立高度停止、预测路径余量、客户端Z漂移、恢复进入／退出、最终位置到位，各有含义。现有V3.1说明中，预测常用2 mm、独立高度停止3 mm，客户端4 mm；V3.2客户端最终位置改3 mm，X终点仍2 mm。

**经验**：不应用一个“3 mm容差”统一替代所有边界。每层应明确参考系、对象、时刻、是否含测量误差与故障动作。

### P42：路径预算耗尽既有数值边界，也有真实绕路

后续V3.4文档记录 `used=370.1, requested=29.9, limit=400.0`。比较只允许64 ULP级舍入余量，不用3 mm到位容差宽放路径预算。

该轮真实日志还记录13次姿态恢复、11次高度恢复；X≈643.07 mm到目标687.26 mm仍需44.19 mm，而剩余约29.9 mm，是真实预算不足。修复浮点比较不会消除这段缺口。

策略：V3.4前伸领先实测X最多20 mm；误差逼近恢复阈值时逐步收短前伸；恢复后0.4秒渐增；退出高度恢复需3个新鲜样本并稳定0.2秒。总400 mm预算保留，先减少反复运动。

## 9. 书脊感知：从整体掩码到局部可见面

### P43：`No book detected in the wrist image`

粗前伸到位不等于腕部目标可识别。可能部分裁切、近景不同分布、低置信度；不能仅由这条日志判定真实没有书。

V3.2先用book定位整书，再用book spine约束书脊，不把整书mask直接当中线区域；失败尝试Canny/Hough左右边界。真实回放里曾出现book 0.17264、spine 0.20690，两者IoU0.99513，新规则可以初始化80点；这只是特定图像回放。

### P44：整书封面混进中线，产生约65 px系统偏移

保存的斜书回放中，整书中心列u=569.95 px，显式书脊u=504.96 px，相差约65 px；书脊角度36.42°。证据：[斜书结果](../RobotRAM/output/v32_spine_only_20261011/spine_only_result.png)。

策略：用书脊可见两侧定义中线，点只在每行内侧60%且留足LK窗口边缘余量的区域初始化；保留遮挡孔洞，不为凑点扩到封面。

### P45：透视下左右边不平行，旧角差阈值拒绝真书脊

V3.3取消“方向差>5°就拒绝”的单一门槛，改检查可见区间宽度：不交叉、不小于8 px，端点宽比≤1.8，宽度变化与线性残差受限。

边界备用同时核对真实边缘支持与连续亮度／颜色阶跃，防止将文字笔画、大片空白或书间缝误作书脊。真实失败图中方向差5.21°、宽比1.477、边缘支持98.56%／100%的候选通过，说明不能把二维平行当作透视投影的必然条件。

### P46：长边断裂、等亮度异色、重复候选

V3.4历史边界方案尝试LSD短线段连接、Huber拟合、灰度和Lab颜色支持；连接仅产生候选，仍要对原像素核验，不能补出不存在的边。

两个近乎相同边界拟合可能被误当两本书。增加重复候选合并：共同支持区间、左右边偏差、区域IoU满足条件，且组内两两一致才合并；仍保留相邻条带歧义拒绝。一次真实回放IoU98.19%，2组变1组，但对人工平移12 px后的图仍可能失败；不能宣称普遍鲁棒。

### P47：SAM3无书脊时，使用GPT备用

用户提出 SAM3 没有可靠book spine时用GPT-6分割。早期方案为GPT四边形＋SAM2细化，再接原几何／深度验证；后续按需求改为GPT直接四边形栅格化，避免SAM2再次扩到封面，也减少不必要的embedding开销。

因此“GPT分割”在最新直接区域路径中是**四边形区域提议**，不是经标注验证的精细像素分割。GPT置信度是模型返回字段，不是校准后的成功概率。GPT提供像素区域，不输出机器人XYZ或电机动作。

### P48：V3.3启用真实最高分辨率，保持旧消费者兼容

共享服务同时提供旧848×530和原始1280×800。V3.3使用原始RGB及同帧对齐深度，内参按像素中心缩放规则换算；外参和毫米单位保持。不是将低分辨率图放大后称最高分辨率。

真实只读验证记录MJPG/Y16、10 FPS，全帧有效深度约74.46%；有效比例不等于书脊深度准确率。证据：[原始分辨率验证目录](../RobotRAM/output/v33_native_validation/)。

### P49：V3.4后续策略更新，以新版分支为准

当前README顶部增量记录了后续变化：

- SAM3书脊不通过时改用GPT腕部区域；在线V3.4不再走原边界配对备用，边界模块作为历史实现和离线对照保留。
- 跟踪几何共识失败时先确认保持，再用新腕部图GPT重圈书脊；新跟踪器必须再经新图、位姿配对和连续性验证。每轮最多恢复2次，不重置Z、X终点、时间或路径预算。
- 探测阶段发生跟踪器切换，要废弃跨模板差分并重新辨识Jacobian。
- 头部三维倾角相对基座竖直超过45°会触发GPT复核；复核后仍不可靠可跳过可选J7预旋转，不能把错误角度直接下发。
- 头部GPT直接区域曾按用户要求跳过原书脊中心深度离散度拒绝／稳定区回退，但仍需有效实测深度；输出需标记检查被跳过，不能把混合深度称可靠。
- 初次腕部感知无论成功失败均保存 `first_detection.html`，伺服快照仍每200帧一次。

这些更新来自现存V3.3/V3.4文档和代码线索；部分仅做模拟API或历史图片回放，不应补写成每项都经过真实API和实机抓取验证。

## 10. 三维工作空间与头部 AR 分支

### P50：需要看到右臂三维可达范围，而不仅是坐标数字

从URDF腕部坐标系可视化，发展到右臂工作空间采样，再限制“夹爪水平向前”。这里水平向前对应末端局部−Z对齐基座+X，roll自由。

[水平向前工作空间统计](../RobotRAM/output/right_arm_workspace_20261010/forward_stats.json)记录约300972个样本、显示10007个、20 mm体素。坐标为SJ4Z、目标为`arm_end_effector_r`，不是指尖。采样包络未做自碰撞、躯干／左臂／环境碰撞和路径可达检查。

**论文应说明**：工作空间点云是给定关节与姿态条件下的采样结果，不是每点均可安全到达的证书，平滑表面也不是IK保证。

### P51：把手所在高度平面叠加到真实头部图像

用户希望像游戏中的范围提示一样显示三维平面，结合深度表达遮挡／穿透关系。实现逐步经历彩色平面、金色物体轮廓、取消轮廓、改为水面式明暗，再调整金色浓度。

最终约定：工作空间平面以上的真实表面保持原色，平面以下按真实深度压暗；无效深度不瞎填。物体轮廓高亮取消，逐像素遮挡裁切关闭，但深度明暗功能保留。

### P52：平面到底取哪个高度

AR当前参考是`arm_end_effector_r`原点在`dummy_world`中的Z，不是指尖或另带工具偏置的`arm_tool_pose`。既有SJ4Z样本变换到dummy_world时涉及342 mm的Z平移。

这与伺服程序固定TCP的Z不应混淆。AR高度定义、控制TCP和夹持位置需要在论文坐标图中分别画清楚。

### P53：画面闪烁、旧帧消失、手升高后平面没跟上

无新图／无新状态时清空覆盖层，会造成闪烁；仅有相机实时不等于手部状态实时。渲染不应每次把局部旧新数据混合。

策略：保留上一完整RGB＋AR＋高度帧，新帧完成解码再替换；数据超时或断连明确标示暂停。图像、关节状态、平面应来自时间一致的快照，不能用旧高度叠在新图上冒充当前场景。

深度噪声会使平面附近像素明暗跳动，因此显示采用过渡区等平滑处理；显示稳定性处理不能篡改供抓取使用的原始深度。

### P54：Remote断开后不恢复、Ctrl+C才能重启

用户要求持续监听Connect/Disconnect。AR状态旁路持续等待实际PanelState，断开后暂停，重新有新报文则恢复，而非一次异常永久退出。

状态来源应是新鲜面板反馈；规划器缓存可能在上游断开后仍重复旧值，不能仅凭UDP仍有包就说机器人状态在线。旁路捕获还需减少抓包缓冲；AR不得抢占控制端口或自动启动机器人。

### P55：AR和抓书争用同一头部相机

用户提出类似ROS的一源多用。实施为本机 `head_rgbd` 最新帧HTTP服务（127.0.0.1:8792），AR页面在8791，多个消费者独立游标。**目前不是ROS topic。**

RGB、float32毫米深度、标定、时戳和帧序号原子打包；只保留最新帧，不累计队列。AR渲染不污染抓取图像。服务负责设备重连，客户端负责数据时效。

AR可以保留旧帧供观察；控制端不能用旧帧继续运动。两者容错策略刻意不同。AR停止只退出订阅，不关闭其他消费者的相机。

## 12. 通用特征Skill与独立 servor.py

### P59：从书本专用程序抽出通用视觉对准

## 14. 当前方法应如何在论文中准确描述

### 14.1 任务相关视觉特征，而非统一套用图像中心

早期四点最终示教误差为8维，CoTracker中心误差为2维；后续书脊／标记对准误差为：

```text
e = [u_center_at_reference_row − u_target,
     image_axis_angle − target_axis_angle]
a = [base_Y_mm, tool_roll_deg]
Δe ≈ J_image · Δa
Δa = −gain · (JᵀJ + λ²I)⁻¹ · Jᵀe
```

这里给出的是研发中阻尼最小二乘控制的概念形式；具体归一化、阻尼和裁剪以对应版本函数为准。两个特征分量单位分别是像素和角度，不能忽略量纲直接比较gain。探测应使用实测ΔY/Δroll，而不是请求位移。

中心线的定义来自物体可见表面几何，特征点身份负责跨帧传播；这与点云质心控制、目标检测框中心控制有区别。

### 14.2 视觉对准和前伸终点解耦

头部RGB-D提供基座X终点，腕部视觉减小横向和方向误差。完整前伸不依赖同一书本示教纹理，因此能更换书本；代价是需要正确粗目标及深度、指尖偏置和安装关系。

用“按深度到达终点”描述距离模式，用“视觉误差连续满足条件”描述视觉对准；两者同时满足与单独满足必须区分。

### 14.3 双层闭环和三种频率

- 感知／视觉目标更新：配置上限10 Hz，真实受相机、配对、跟踪及ACK约束。
- 差分伺服后端：标称50 Hz，把TCP误差映射为有限关节位置命令。
- 底层驱动／滤波：另有控制周期、速度比例和RAW低通行为，本文不将其频率与50 Hz混为一谈。

高gain、无限前瞻、短轨迹时间各改变不同对象。真实提速应报告端到端延迟、实际TCP速度、跟踪误差和振荡，而不是只报告配置频率。

### 14.4 从“失败就退出”到可解释的有限恢复

恢复机制有不同对象：相机设备重连、位姿配对重采、同模板重定位、书脊GPT重新区域化、丢点后距离退化、直接伺服高度／姿态恢复。应分别画状态机并说明：恢复条件、最大持续时间、是否继续前伸、是否允许重定义目标、哪些预算不重置。

不是所有失败都应恢复：错误身份、歧义、碰撞、不可用反馈或未知深度不能通过默认选一个继续。

## 15. 可以形成的研究问题与后续实验

以下是论文准备建议，不是已经完成的实验或已证实的创新点。

1. **跨视角身份 vs. 场景假设**：对同一批标注目标比较SIFT、XFeat、SuperPoint＋LightGlue，固定输入分辨率、ROI和几何准入；报告同书识别与控制点转移误差，不能只报内点数。
2. **最高原始分辨率的增益**：对848×530与1280×800同时记录目标像素面积、正确匹配率、误匹配率、耗时；分别评估整图与ROI，避免放大图冒充新信息。
3. **目标定义消融**：整书质心、书脊mask中线、左右边界中线、语义中心＋固定特征传播。重点测斜书、封面可见比例和部分出画时的横向偏差。
4. **控制结构消融**：逐步CuRobo、滚动轨迹、直接差分伺服；统一速度／约束，比较总时长、路径、停止次数、Z漂移和到位误差。
5. **时序消融**：未配对、主机时戳插值、加入已知时延扰动；记录图像年龄、反馈年龄、插值支撑、拒绝率和误差。
6. **增益／前瞻／滤波联合实验**：单独改变gain，分别启闭目标渐增和前瞻限制，固定底层RAW参数；验证为何高gain在解除执行瓶颈后引起振荡。
7. **恢复与退化模式**：人工遮挡、减少特征、几何共识破坏、相机短断连、反馈短中断；记录是否恢复同一目标、实际前伸是否停止、恢复耗时及最终状态。
8. **车把标记安装与尺寸**：20 mm实际黑框，测距离、倾角、模糊、弯曲和遮挡对检测率的影响；校准标记到杆中心／夹爪中心的真实偏置。
9. **抓取成功定义**：加入物体保持、滑移或力／接触证据，区分“到位”“合爪”“夹住”“稳定保持3秒”“按序释放返回”。
10. **任务外推**：书本、盒子、工具平面标签与车把分别统计，不用单一书脊样本证明所有物体泛化。

每组实验应保存失败轮，预先定义成功／失败标准，报告样本数与不确定性；不要仅挑成功截图。论文的实时性、精度和成功率只能来自正式测量。
