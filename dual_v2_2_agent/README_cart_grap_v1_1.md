# cart_grap_v1_1：最终保持后的视觉闭环

运行方式（原V1保留）：

```bash
cd /mnt/ssd/user/V/dual_v2_2_agent
/mnt/ssd/robotarm/env/robotram_wx/bin/python cart_grap_v1_1.py --check-config
/mnt/ssd/robotarm/env/robotram_wx/bin/python cart_grap_v1_1.py --execute
```

`--execute`默认重复执行：每轮先归位并重新测量，完整抓取、松开、撤回及返回成功后等待5秒再开始下一轮。按`s`在本轮结束后停止；失败保持暂停，检查后按回车重试，`Ctrl+C`中断退出。需要交互终端监听按键。仅执行一次用`--execute --once`。每轮独立输出目录；指定`--out`时其下生成`round_0001`等子目录。

前伸不是固定100 mm：`总前伸 = 标记基座X + 100 mm伸入量 - 指尖X投影偏移 - 起始TCP X`。粗前伸占总量40%（最多100 mm），余下由视觉闭环完成，单次X目标上限6 mm。最近保存的成功轮次`cart_grap_v1_1_1791815471095799414`总前伸80.53 mm、粗前伸32.21 mm，余下约48.32 mm；每轮重新测量会改变这些值。

不加`--execute`仍只生成方案，不复位。沿用`cart_grap_v1_config.json`、其alignment/approach配置和现有规划器。`--execute`先执行右臂`first_reset`，通过CuRobo重新规划，确认规划器完成、控制器空闲、关节误差≤0.3°、至少3个新反馈且稳定≥0.2秒；归位成功后才记录起点和采集目标。工作高度为归位后的Z+30 mm，最终返回归位后记录的位置。要求右夹爪已实际打开；不会自动松开持有物体。归位失败停止整轮。

归位使用新的强制指令，即使已经接近复位点也不会跳过请求，避免沿用上轮取消保持留下的失败状态。它不绕过规划器碰撞、状态或关节限制。日志为`first_reset_start`和`first_reset_confirmed`。

归位确认后先预热腕部、头部相机，丢弃头部预热帧，再等待TCP稳定（最多8秒）：一秒窗口内相对参考位移≤0.15 mm、姿态变化≤0.1°、最大关节速度≤0.005 rad/s、控制器空闲且至少3个新样本。窗口超差重启，但不延长总超时。执行模式在预热、稳定和采集期间持续核对归位关节误差≤0.3°以及规划器回显仍为原归位目标，不能将偏离归位目标的位置当成新原点。首次归位确认仍要求完成状态9；之后允许同一目标的4（规划成功）/9（运动完成）切换，因为9由每帧反馈派生，并不锁存。初始化、重新规划、IK及故障等其他状态仍中止，错误记录实际状态码。

通过后才从同一确认样本更新初始TCP、关节、姿态与工作高度，并采集新的GPT输入图。日志顺序为`acquisition_cameras_warmed`、`tcp_settle_start/confirmed`、`acquisition_anchor_locked`。采集期间仍是原来的0.5 mm/0.25°/0.02 rad/s保护，不会在GPT等待中重置基准；若仍漂移会停止。这是采集衔接修复，不能证明硬件或执行端的残余运动已根治。现有规划器无改动，只需重启抓车程序。


变化：视觉误差进入较小范围（水平≤1.5 px、角度≤0.75°）才锁定最终保持目标；保持中和夹紧前复查继续使用原3 px/1.5°要求。保持后读取三张新图与配对位姿；短暂超差返回同一轮视觉纠偏，不重新探测Jacobian，也不重置120秒和路径预算。丢码沿用限时重识别，状态故障/高度越界仍立即失败。只有最终复查通过才输出`cart_aligned`、进入夹紧；确认后不再额外发一次保持动作。

日志新增`final_alignment_retry`与`final_alignment_confirmed`，结果目录为`output/cart_grap_v1_1_*`。GPT/RGB-D、粗运动、夹紧停顿3秒、松开、-X撤回100 mm沿用V1。加入循环后79项离线回归通过；此次修改未启动实机运动。
