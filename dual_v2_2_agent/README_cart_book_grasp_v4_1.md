# V4.1：自动选择书上沿、独立跟踪手指、连续倾书伺服

## 最新任务更正（2026-10-13，待接入运行代码）

用户明确要求：**头部 RGB-D 求上沿相对书脊中心的三维偏移 → 自动粗定位 → 腕部视觉伺服把指定指腹搭到上沿**。先完成搭上沿，再推进倾书阶段。下文头部单视角、人工预先靠近的运行方式属于已有实现，不代表本次要求已完成。

用基座坐标下同一本书的书脊中心 C 与真实上沿接触参考 E 计算 Δ=E−C，分别保留 ΔX、ΔY、ΔZ；倾斜书不能只取半书高。粗目标 TCP = C+Δ+[0,0,预留间隙]−R_base_tcp·p_pad_tcp，指定指腹保持水平。物体内部偏移不能直接加到当前 TCP，旧整夹爪50mm偏移也不能代替指腹接触偏移。

粗到位后由腕部观测上沿固定参考，通过 Image Jacobian 连续修正局部误差。视觉目标对应实际指腹接触位置（标定投影或等效示教参考），不默认图像正中心；局部平面对准后再有限接近。只看二维投影重合不能证明已接触。当前程序尚未接入自动粗定位和腕部近接链路；此前离线测试只覆盖原头部方案。

## 特征选择与跟踪

- GPT 选择同一书面的真实上下边：允许书脊或封面，但不能将两个平面合成一个面；排除文字框、邻书、书架。初始化/语义恢复需要实际上沿及支撑底边可见，不猜被遮住的角。
- 在书面内按空间网格选真实纹理点，用 LK 前后向检验与 RANSAC 单应传递固定语义参考。控制点是实际三维上沿的初始中点投影，不是纹理点质心。底边中点和方向提供支轴。
- 手指侧面使用另一个独立跟踪器。它的下长边与标定指腹边缘投影匹配，确定同一物理参考；不把书纹理与手指纹理混合拟合。
- 正常帧使用局部光流；光流失效时，在上一位置附近裁剪 ROI，使用原模板 SIFT 双向比率匹配重定位。同一原始模板和参考点保留。没有逐帧全图分割或每帧 GPT。
- 内点覆盖面积、每帧几何变化和语义边附近的纹理支持均检查。只剩中央文字时不继续远距离外推上下边。边坐标标记为“固定语义点经单应传播”，不是声称每条边均被逐帧独立检测。
- 本地恢复失败后，保持机械臂并让 GPT 对照原图确认同一本书/同一根手指；新的分割还须通过真实深度、新帧跟踪、与上次三维位置/尺寸连续性检查，以及控制器原支轴检查。不得重新置零倾角或预算。

运行中无需每帧直接检测完整四角，但必须有足够的同平面纹理支撑上下参考；大片遮挡导致支撑不足仍会暂停。无纹理、反光、相似书本身份歧义仍可能失败，本版不保证任意视角可用。

## 指腹视觉输入与标定

`cart_book_grasp_v4_1_config.json` 中仍需实测：

- `pad.center_tcp_mm`：长指腹下表面中心在控制器 TCP 局部坐标中的毫米位置。
- `pad.normal_tcp`：向书的外法向，水平指腹时变换到基座后朝下。
- `pad.along_tcp`：长轴方向，与法向垂直。
- `pad.length_mm / width_mm / edge_margin_mm`：可用面尺寸和边缘余量。
- `calibrated_gripper_position`：标定时右夹爪实际归一化开度0～1；运行偏差超过0.01停止。

实际测量后才设置 `pad_calibrated=true`；核对当前手指、水平近接姿态、支轴、场景空间和标定后设置 `scene_setup_confirmed=true`。旧整夹爪50mm偏移不能直接代入。

`pad_visual_required=true` 为默认。图像中观测的是手指侧面下边缘的固定点，**其深度仍来自配对 TCP 和指腹几何**，不直接取混合边界深度。该点的图像残差换算成有限的基座位移修正，再用于指腹/上沿误差；超过3mm的图像/FK分歧停止，不能靠这个偏移掩盖错手指或坏标定。该方案不是指腹完整 RGB-D 测量，也不能自动校正沿视线方向的全部误差。

书面三维量由同帧实测深度的内部平面拟合得到，上下边由射线与平面求交；没有让 GPT 生成深度或机器人位姿。混合平面、深度缺失等故障不走 GPT 强制通过路径。

## 连续控制与恢复

固定头部相机的混合图像特征为 `s=[X/Z,Y/Z,log(Z)]`。Image Jacobian 将指腹图像/距离误差转换为连续 XYZ 平移，保持工具姿态。视觉更新配置上限10Hz，执行器目标50Hz，末端速度上限10mm/s，视觉目标领先≤2mm；这些是配置，不是实测速率。

流程为水平对准上沿→接近视觉间隙→有限倾转试探→依据书的实测响应继续倾转→到期望角后保持。不把二维像素重合当成力接触，也不把手腕转角当书倾角。书不响应时，试探目标不累计，2秒有效试探时间内无响应停止。未接入力反馈，水平指腹可能滑动而无法带动书。

恢复使用 V4.1 专用 `book_v4_1_pause`：清除旧运动输出，经通信线程锁定实测关节保持；客户端等待新鲜目标回显和连续0.3秒稳定反馈，之后才请求 GPT。API 等待期间持续检查反馈、夹爪、姿态和0.5mm保持漂移。暂停最多75秒，碰撞/限位/断流等锁存故障不能被暂停或恢复清掉。恢复时保留原XYZ包络、支轴、角度、路径和总时间预算；仅从书响应计时扣除已确认的暂停时间，同一个试探目标仍不变。

正常运动中0.3秒无新视觉目标保持，1秒无新目标锁存停止；显式感知暂停不发送新的运动目标，底层 RT 通信断流保护保留。图像/位姿按主机时间配对，缺配对短暂等待，持续失败停止；不是硬件曝光同步。

Ctrl+C/故障请求取消并保持，不自动松爪或复位；通信失败时日志区分保持请求与确认。接触摩擦、遮挡可见性、深度精度和真实轨迹效果仍须实机验证。
